## 1. この文書で使う言葉

| 言葉 | 意味 |
|---|---|
| スプレッドシート | Google スプレッドシートのファイル1つ。中に複数の「タブ（シート）」を持てる |
| 同期用のタブ | アプリが書き込むタブ。名前は **`trades`**（3章）。オーナーは中身を手で直さない |
| 見出し行 | タブの1行目。列の名前を並べた行 |
| 表示形式 | セルの値をどう見せるかの設定（スプレッドシートの「表示形式 → 数字」）。値そのものは変えない |
| `@` の書式（書式なしテキスト） | 表示形式の一種で、「このセルは文字として扱う」という指定。入れた文字を日付や数値に読み替えなくなる |
| Apps Script | Google が無料で提供している、スプレッドシートを操作する小さなプログラムを動かす仕組み。アプリはここに記録を送り、Apps Script がシートに書く |
| 上書き（行の更新） | 同じ記録（同じ `id`）の行がすでにあれば、その行の値を新しい値に入れ替えること |
| CSV インジェクション | 表計算ソフトが、`=` などで始まる文字を数式として実行してしまう問題（architecture 14.2） |
| 往復（ラウンドトリップ） | シートを CSV で書き出し → アプリの「CSV を読み込む」（T-44）で戻したとき、元の記録と同じ値に戻ること |

## 3. スプレッドシートとタブの形

| 項目 | 決めたこと | 理由 |
|---|---|---|
| ファイル | オーナーの Google アカウントにスプレッドシートを1つ作る（名前は自由。T-39 で手順を書く） | 無料。Apps Script をこのファイルに付ける |
| 同期用のタブの名前 | **`trades`**（変えない） | Apps Script はこの名前でタブを探す。名前を変えると書き込めなくなる（エラーで知らせる：10.2） |
| デモ・本番 | **1つのタブにまとめ**、`accountType` 列で区別する（Q-17） | フィルタで分けて見られる |
| 1行目 | 見出し行（4章の32の名前）。**1行目を固定表示**にする | スクロールしても列名が見える |
| 2行目以降 | 1行＝1記録。並びは「送られてきた順」（新しい記録が下に足される）。並べ替えはオーナーが自由にしてよい（6.4） | Apps Script は行の位置ではなく `id` で行を探すため |
| 削除済みの行の見た目 | `deletedAt` に値がある行を**灰色の文字**にする（条件付き書式。Apps Script が最初に設定する） | 削除済みが一目で分かる。列は増やさない |
| スプレッドシートの設定 | 「地域」を**日本**、「タイムゾーン」を**東京（GMT+09:00）**（T-39 で手順に入れる） | 地域によって小数点がカンマになり、CSV に書き出したときの数値の形が変わるため |
| 集計・見やすい表 | 同期用のタブは触らず、**別のタブ**で関数（`=QUERY(trades!A:AF, …)` など）やピボットテーブルを使う | 同期用のタブは書き込みのたびに上書きされるので、手で足した計算が消える・ずれるのを避ける |

### 4.2 シート固有の列（今は0列）

| 候補 | 足すか | 理由 |
|---|---|---|
| 削除済みの印（例：「削除済み」列に ✓） | **足さない** | `deletedAt`（AD 列）に日時が入っていれば削除済み、という同じ情報がすでにある。Q-16 の「削除済み」列はこの列が担う。見た目は灰色の文字（3章）とフィルタの「空白」で十分に分けられる。同じ意味の列が2つあると、食い違ったときにどちらが正しいか分からなくなる |
| 最終同期日時（シートに書いた日時） | **足さない** | `syncedAt`（AC 列）に「この行を送った日時」を入れる（6.3）ので、同じ役目を果たせる。Apps Script 側で時刻を作らないので、Google 側のタイムゾーンの設定にも左右されない |
| 書き込み回数・送った端末など | 足さない | 1台の端末で使う前提（Q-20）で、今のところ使い道がない |

**シート固有の列が0列だと、シートを CSV で書き出したものが、アプリの CSV とまったく同じ列になる**（7章）。T-44 は特別な扱いなしで読める。

**将来シート固有の列を足すときのルール**

1. **AG 列より右に**足す（A〜AF の32列の並びは変えない）。
2. 見出しは `sheet` で始まる名前にする（例 `sheetNote`）。アプリの項目名と重ならないようにするため。
3. T-44 は「知らない列は読み飛ばす」前提にしておく（7.2）ので、足しても取り込みは壊れない。
4. requirements 6.1 に項目が増えた場合（DB の版を上げる作業。architecture 6.11）は、新しい項目を AF の後ろではなく **CSV の列の並びに合わせて**入れ直す必要がある。そのときはこの表と T-38 の見出しの確認、T-44 を同時に直す（pm・engineer・sheets-integrator で相談）。

### 4.3 アプリから送る値（T-41・T-38 の前提）

- アプリは1件ごとに「**見出しの名前 → 値**」の組を送る（並びではなく名前で対応させる。列の取り違えを Apps Script が見つけられるようにするため）。
- **値は `js/csv.js` と同じ作り方**にする（同じ関数を使い、作り方を2か所に書かない）：
  - 文字の列：`cellText`（null は空の文字、配列は `joinList`、先頭が `=` `+` `-` `@` タブ CR なら `'` を付ける `guardFormula`）。
  - 数値の列：**JSON の数値**として送る（`150.25` のように引用符を付けない）。未入力は `null`。有限でない値（NaN など）は `null`。
  - `imageCount`：`imageIds` の要素数（数値）。
  - `syncStatus` は `synced`、`syncedAt` は送る時刻（6.3）。
- 1件ごとに、価格の表示形式を決めるための**価格の小数桁**（`getPairSpec(pair).priceDecimals`：3 か 5）を列とは別に添える。Apps Script に通貨ペアの規則（fx-rules 10.4）を二重に書かないため。届かなかったときは「`/JPY` で終われば3、それ以外は5」で補う。
- 下書き（`drafts`）は送らない（requirements 6.4）。

## 5. シートに日付・数値を勝手に変換させない方法

### 5.1 何もしないと何が起きるか

Apps Script の普通の書き込み（`Range.setValues`）は、**人がセルに打ち込んだときと同じように文字を読み替えます**。たとえば次のようになります。

| 送った文字 | 列 | 何もしないと起こりうること | 困ること |
|---|---|---|---|
| `2026-10-15T21:30:12+09:00` | 日時の列 | 日付・時刻の値に変わる、または表示が `2026/10/15 21:30:12` などに変わる | CSV に書き出すと形が変わり、T-44 で読めない。タイムゾーンの設定で時刻がずれるおそれ |
| `3/4`（タグ・感情の名前） | タグなど | 3月4日の日付になる | 選択肢の名前が壊れる |
| `001`、`1e3`（メモ） | メモ | 数値の `1`、`1000` になる | メモが壊れる（先頭の0が消える） |
| `TRUE`、`50%`、`¥1,000`（メモ） | メモ | はい/いいえの値、`0.5`、金額の `1000` になる | 同上 |
| `=HYPERLINK(…)`（メモ） | メモ | 数式として動く | CSV インジェクション（5.4） |
| UUID（`id`） | A 列 | 今の形（ハイフン入り）では数値・日付にはまずならないが、保証はない | 行を探せなくなる |
| 数値の `150.1` | 価格 | そのまま数値。ただし表示の桁がペアと合わず `150.1` と見える | 見づらいだけ（値は正しい） |

### 5.2 方式の比較

| 方式 | やり方 | よい点 | 困る点 | 判定 |
|---|---|---|---|---|
| A. 列の書式を `@` にする | Apps Script が、値を書く前にその行の書式を設定する（文字の列は `@`、数値の列は桁を決めた形式） | Apps Script の標準機能だけでできる（オーナーの設定作業が増えない）。セルの中身が送った文字そのものになる。数値の列は数値のまま集計できる | 先頭が `'` の文字（CSV インジェクション対策の印）を `@` のセルに書いたとき、`'` が残るかを実際に確かめる必要がある（5.5） | **不採用**（当初の推奨。2026-10-26 の本物の自己テストで、先頭の `'` が1つ取り除かれた：5.5） |
| B. 文字の前に `'` を付けて送る | すべての文字の先頭に `'` を付けると、シートは「これは文字」と受け取り、`'` は表示されない | 書式に頼らない | CSV インジェクション対策の `'` と意味がぶつかる（`'=…` の印が消え、シートを CSV にしたとき `=…` が裸で出る。元から `'=` で始まるメモは T-44 で戻すと壊れる）。日時にも `'` が要る | 採らない |
| C. Sheets API の「そのまま書く」指定（RAW） | Apps Script の「詳細サービス」で Sheets API を有効にし、読み替えなしで書く指定で書き込む | 仕様として読み替えも数式の実行もしないことが保証されている | オーナーのセットアップに「サービスの追加」の手順が1つ増える。コードが少し長くなる | **決定**（2026-10-26。表示形式の設定は A と同じで、値の書き込みだけを RAW にする：5.3） |
| D. 全部の列を文字にする | 数値の列も `@` にして文字で書く | 往復は完全に一致する | 合計（`SUM`）などの集計に数値として使えない。集計用の控えという目的に合わない | 採らない |

### 5.3 決定：表示形式と値の書き方（T-38 で実装。2026-10-26 に方式 C に決定）

1. Apps Script は、1行を書くたびに、**先に A〜AF のその行の表示形式を設定し、確定させ（`SpreadsheetApp.flush`）、そのあと値を Sheets API の RAW 指定で書く**（列全体に一度設定するだけだと、行を足したときに書式が引き継がれない場合があるため、毎回設定する）。表示形式の設定は方式 A のときと同じで、値の書き込みだけが違う（11.7）。
2. 表示形式は次のとおり（4.1 の「表示形式」列と同じ）。

| 列の種類 | 列 | 表示形式 | 見え方の例 | 理由 |
|---|---|---|---|---|
| 文字 | A〜D・F・M・P・R〜Z・AB〜AF | `@` | 送った文字のまま | 読み替えを止める |
| 価格 | E・I・J・L | 価格の小数桁が3なら `0.000`、5なら `0.00000`（行ごと） | `150.000`、`1.08510` | アプリの画面と同じ桁で見える（fx-rules 10.4）。入力できる桁の上限と同じなので、値が丸められて見えることはない |
| ロット | G | `0.00` | `1.00`、`0.10` | ロットは小数第2位まで（fx-rules 8.2 E-06） |
| 整数 | H・O・AA | `0` | `10000`、`-1885` | 3桁区切りを付けない（CSV に書き出したときに `2,500` となり、取り込めなくなるため：7.1） |
| リスクリワード | K | `0.00` | `2.00` | アプリと同じ桁（fx-rules 6.1） |
| pips | N | `0.0` | `25.0`、`-37.7` | アプリと同じ桁（fx-rules 6.1） |
| 円換算レート | Q | `0.000` | `149.850` | レートは小数第3位まで（fx-rules 8.2 E-08） |

3. 値は**数値の列には数値、文字の列には文字**で書く。未入力は空のセル（`0` を入れない）。
4. Apps Script は日時を自分で作らない・日付の値として扱わない（日時はいつも文字）。
5. **A〜AF 以外の列には書かない**（オーナーが右側に何か書いても消さない）。

- 価格の見え方の補足：アプリは価格を数値で保存しているので、`150.100` と入力した価格は `150.1` として記録されています（architecture 6.7）。シートでは表示形式で `150.100` と見えますが、セルの値は `150.1` です。
- 3桁区切りの付いた見やすい損益を見たいときは、別のタブで `=TEXT(…)` を使うか、そのタブの表示形式を変えます（同期用のタブの表示形式は変えない。書き込みのたびに戻るため）。

### 5.4 CSV インジェクション対策との関係

- アプリの CSV（`js/csv.js`）は、文字のセルの先頭が `=` `+` `-` `@` タブ CR のとき（または `'` のあとにそれらが続くとき）、先頭に `'` を1つ付けます（`guardFormula`。architecture 14.2）。
- シートにも**同じ印の付いた文字をそのまま入れます**（4.3）。こうすると：
  1. シートの中で数式として動かない（`@` の書式の文字で、しかも先頭が `'`）。
  2. シートを CSV に書き出して Excel で開いても、アプリの CSV と同じく `'` が付いたまま＝数式にならない。
  3. T-44 は、アプリの CSV と**同じ規則**（`unguardFormula`：先頭の `'` のあとに危険な文字が続くときだけ `'` を1つ外す）で元に戻せる。
- シートの見た目では、印の付いたメモは `'=…` と `'` が見えます（アプリの CSV を Excel で開いたときと同じ。安全を優先した割り切り：architecture 14.2）。
- **Apps Script 側の守り**：文字の列の値が `'` を付けずに `=` `+` `-` `@` タブ CR で始まっていたら、その記録は**書かずに受け付けない**（アプリは必ず印を付けて送るので、そうなっていないのはアプリの誤りか、アプリ以外からの送信）。印を付け直す処理は入れない（二重に付けると `''=…` になり、戻したときに値が変わるため）。
- R-12（Excel で全角の「＝」や先頭に空白のある「 =」が数式になるか）の結果で `guardFormula` の対象を広げる場合は、**Apps Script の守りの規則も同時に広げる**（csv.js・T-44 の `unguardFormula`・この節を一緒に直す）。

## 6. 1行＝1記録（`id` での追加・上書き）

### 6.1 書き込みのルール

| 状況 | Apps Script の動き | 結果として返すもの（T-38 で確定した名前：11.4） |
|---|---|---|
| `id` の行がない | 一番下に**行を追加** | 追加した（`added`） |
| `id` の行があり、届いた `updatedAt` が行の `updatedAt` **より新しい** | その行の A〜AF を**まるごと上書き** | 更新した（`updated`） |
| 同じ（**等しい**） | まるごと上書き（同じ内容の送り直し。`syncedAt` だけ新しくなる） | 更新した（`updated`） |
| **古い** | **書かない**（シートにある新しい内容を残す） | 古いので書かなかった（`stale`。アプリは送り直さない：10.3） |
| 値の形が決まりと違う（5.4・10.2） | その記録は書かない | 受け付けなかった（`rejected` と理由のコード） |

- `updatedAt` はいつも固定形式の25文字（architecture 6.6）なので、**文字のまま比べれば時刻の順**になります（日付の値に直さない）。
- 行は**毎回 A 列から `id` を探して**見つけます（行番号を覚えておかない）。オーナーが並べ替えても正しい行に書けるようにするためです。
- 同じ `id` の行が2つ見つかったとき（手でコピーした場合など）は、上の行を使い、下の行は触りません（結果に「重複あり」を添える）。
- 二重に行が増えないよう、Apps Script は書き込みの間**ロック**（同時に1つの処理しか書けないようにする仕組み）をかけます。アプリも**1度に1つの送信しかしない**（T-42）。送信が終わる前に次を送らないので、古い内容があとから届いて新しい内容を上書きすることも起きにくくなります。
- `updatedAt` は秒単位のため、**同じ秒の中の2回の変更は「等しい」**になります（R-05）。上のルールでは等しいときは上書きするので、あとから送った方（＝新しい方）が残ります。1度に1つしか送らない前提で成り立つので、T-45 の観点に入れます。

### 6.2 削除・削除の取り消し・決済の取り消し

| 操作（アプリ） | 記録の変化 | シートの行 |
|---|---|---|
| エントリー | 新しい記録（`status`＝`open`） | 行が追加される |
| 決済 | 決済価格・日時・pips・損益などが入る（`closed`） | 同じ行が上書きされる |
| 編集 | 値が変わる | 同じ行が上書きされる |
| 決済の取り消し | 決済の値が空に戻る（`open`） | 同じ行が上書きされ、決済の列が空欄に戻る |
| 削除（論理削除） | `deletedAt` に日時 | **行は消さない**。`deletedAt` 列に日時が入り、灰色の文字になる（Q-16） |
| 削除の取り消し | `deletedAt` が空に戻る | 同じ行の `deletedAt` が空欄に戻り、普通の色に戻る |
| 一度も送らないうちに削除した記録 | `deletedAt` 付きで未送信 | **それでも行を追加する**（削除済みとして残る。記録の履歴をシートでも追えるように） |

### 6.3 `syncStatus` と `syncedAt` の列に入れる値

送る時点の記録では、`syncStatus` は `pending`（未送信）か `error`、`syncedAt` は「前回」成功した日時です。そのまま書くと、シートには「未送信」と書かれた行が並び、最終同期日時も1回分遅れて見えます。そこで次のように決めます。

- アプリは、送る直前に「送る時刻」を1つ決め、**`syncStatus`＝`synced`、`syncedAt`＝送る時刻**として行の値を作る（4.3）。
- 送信が成功したら、アプリは記録の `syncStatus` を `synced`、`syncedAt` を**同じ「送る時刻」**にする（送信中に記録が編集されていなければ：architecture 20.2。`updatedAt` は変えない：architecture 3.3）。
- こうすると、**成功したあとは記録とシートの行が32列すべて同じ値**になります。シートの `syncedAt` 列が「シート側の最終同期日時」の役目を果たすので、シート固有の列は要りません（4.2）。
- 送信が失敗したときはシートに何も書かれないので、シートに `synced` と書かれていても食い違いは起きません。シートに書けたのに応答が届かなかった場合は、アプリが後で送り直し、同じ行が上書きされます（`updatedAt` が等しいので上書き：6.1）。

### 6.4 オーナーがシートを手で触ったとき

| 操作 | どうなるか | 案内（T-39 の手順書に書く） |
|---|---|---|
| 並べ替え・フィルタ・列の幅・文字の色 | 問題ない（`id` で行を探すため） | 自由にしてよい。灰色の条件付き書式は消さない方がよい |
| A〜AF のセルを書き換える | 次にその記録をアプリで変えたときに上書きされて戻る。変えなければ食い違ったまま | 書き換えない。直すときはアプリで直す（一方向：Q-19） |
| 行を削除する | その記録をアプリで次に変えたとき、行が**追加し直される**。変えない記録はシートから消えたまま | 行は消さない（削除はアプリで） |
| 列を足す・消す・並びを変える（A〜AF の中） | 見出しが決まりと合わなくなり、Apps Script が**書き込みを止めてエラーを返す**（10.2）。アプリの同期状態にエラーが出る | A〜AF の列はいじらない。メモ書きなどは別のタブに |
| AG 列より右に自分の列を足す | Apps Script は触らない。CSV に書き出すと余分な列として出るが、T-44 は読み飛ばす（7.2） | してもよいが、別のタブの方がおすすめ |
| タブの名前を変える | 書き込めずエラー | `trades` のままにする |

- シートの行を消してしまった・シートを作り直した場合に備えて、**「全件をシートに送り直す」操作**があると戻しやすくなります（全記録の `syncStatus` を `pending` にするだけで、既存の仕組みで送られる）。必要かどうかは T-42・T-43 で検討します（10.3）。

## 7. シートを CSV で書き出して T-44 で戻せること

### 7.1 アプリの CSV とシートの CSV の違い

シートの CSV は、Google スプレッドシートの「ファイル → ダウンロード → カンマ区切り形式（.csv）」で、**今開いているタブだけ**が書き出されます（具体的な操作は T-39 で書く）。書き出されるのは**セルの見え方の文字**です。

| 項目 | アプリの CSV（T-25） | シートの CSV | T-44 で困るか |
|---|---|---|---|
| 列 | 32列（見出しは 4.1 と同じ） | 同じ32列（シート固有の列は0列）。オーナーが AG 列より右に足した列があれば、それも出る | 困らない（名前で読み、知らない列は飛ばす：7.2） |
| 先頭の BOM | あり | **ない見込み** | 両方受け付ける |
| 行の区切り | CRLF、最後の行にも付く | LF か CRLF、最後の改行がないこともある | 両方受け付ける |
| 数値 | `150.1`、`1`、`2` | 表示形式の見え方で `150.100`、`1.00`、`2.00` | 数値に直せば同じ値。末尾の0は桁数に数えない（fx-rules 8.1）ので、桁のチェックにもかからない |
| 損益・1lot の通貨数 | `2500` | `2500`（3桁区切りなしの表示形式にしたため） | 困らない |
| 日時・文字・根拠・タグ | 保存形式のまま | 同じ（`@` の書式。5.5 で確認） | 困らない |
| CSV インジェクションの印 `'` | 付く | 同じく付く（5.4・5.5） | 同じ規則で外せる |
| 削除済みの記録 | 「含める」を選んだときだけ | **いつも含まれる** | 削除済みとして取り込む扱いが要る（7.2） |
| `syncStatus`・`syncedAt` | 記録の値（`pending` など） | `synced` と送った日時 | 取り込んだ記録は `pending` にする（決定済み：T-44）ので困らない |
| 並び | エントリー日時の古い順 | 送った順、またはオーナーが並べ替えた順 | 並びに頼らなければ困らない |
| 空の行 | ない | 消した行の跡などで、全部空の行が混ざることがある | 全部空の行は飛ばす |

- **Excel で開いて保存し直した CSV は対象外**です。Excel が日時を `2026/10/15 21:30` に、`001` を `1` に変えてしまうためです（アプリの CSV も同じ）。T-39 と T-44 の画面の案内に「ダウンロードしたファイルをそのまま読み込む」と書きます。
- セルの値に表示形式の桁より細かい値が入っている場合（今の入力チェックでは起きない）、シートの CSV では見え方の桁に丸められます。アプリの入力チェック（fx-rules 8.2）で桁が守られている限り、値は変わりません。

### 7.2 T-44（CSV の読み込み）への前提（申し送り）

アプリの CSV とシートの CSV の両方を同じ処理で読めるよう、T-44 は次を前提にしてください。

> design 14.6.11（T-66。オーナー確認待ち）の **⑥「読み込める CSV の範囲」の推奨案**（32列が名前でそろえば順番は問わず、ほかの列は無視。BOM・CRLF／LF を問わない）と **③「削除済みの記録は削除済みのまま取り込む」の推奨案**は、下の #1〜#3・#5 と同じ内容です。**⑥で代案（アプリが書き出した形だけ受け付ける）が選ばれると、シートから書き出した CSV は戻せなくなります**（BOM が無く、数値の見え方も違うため）。

1. **列は見出しの名前で探す**（何列目かで読まない）。4.1 の32の名前がすべてあることを確かめ、足りない・同じ名前が2つあるときは取り込まずに知らせる。
2. **知らない名前の列は読み飛ばす**（シート固有の列・オーナーが足した列）。
3. 先頭の BOM はあってもなくてもよい。行の区切りは CRLF・LF のどちらでもよく、最後の改行はなくてもよい。
4. 数値の列は `150.100`・`1.00` のように末尾に0が付いた形も受け付ける（3桁区切り・全角・指数表記は受け付けない。fx-rules 8.1 と同じ）。
5. **削除済みの行（`deletedAt` に値がある行）がいつも含まれる**ことを前提に、削除済みの記録として取り込む（取り込み前の件数確認で「うち削除済み n件」と分けて見せると分かりやすい。画面は T-66 の designer と相談）。
6. 取り込んだ記録は `syncStatus`＝`pending`（決定済み）。`syncedAt` を残すか空にするかは T-44 で決める（どちらでも同期は正しく動く）。
7. 全部空の行は飛ばす。並び順には頼らない。
8. 文字のセルは、アプリの CSV と同じく `unguardFormula`（`'` を外す）と `splitList`（根拠・タグを分ける）で戻す。
9. `imageCount` からは画像を戻さない（`imageIds` は `[]`。画像は CSV にもシートにもない：8章）。
10. 日時の列には 2000〜2099 年の範囲を当てる（決定済み：roadmap 7.18 #26）。固定形式（25文字）でない日時は、Excel で保存し直した可能性が高いので、その旨を添えて知らせる。
11. **「上書き」を選んで取り込んだときの `updatedAt`**：CSV の値のまま残すと、シートの方が新しい場合、その記録は送ってもシートが「古いので書かなかった」と返します（6.1）。シートにある新しい内容を残す、という意味では安全側ですが、端末とシートの内容は食い違います。取り込みで `updatedAt` を今の時刻にするかどうかは、T-44 で engineer と決める（sheets-integrator の推奨は「CSV の値のまま」。古いバックアップで控えのシートを上書きしてしまう事故を防げるため）。

## 8. 画像は同期しない

- チャート画像はシートに送りません。シートにあるのは **`imageCount`（画像の枚数）だけ**で、アプリの CSV と同じです（requirements F-05・F-07、architecture 14.2）。
- 画像の ID（`imageIds`）も送りません。ID は画像本体（端末の中にだけある）とセットでしか意味がないためです。
- このため、**シートや CSV から記録を戻しても画像は戻りません**（T-44 で決定済み）。画像を残したい場合は、端末の中のデータを消さないことが前提になります（ホーム画面に追加して使う・データの保護。design 14.6.1）。
- Google ドライブへの画像の保存は、将来の拡張の候補として残します（requirements 9章）。

## 9. オーナーに判断してほしい点

> **決定（2026-10-19・オーナーが推奨どおりで決定）**：9.1 は **A（記録〔IndexedDB〕には持たず、端末の設定に「最後のエラー」を1つだけ `syncLastError` として持つ。DB の版は上げないので R-11 は後回しのまま）**、9.2 は **A（見出しは CSV と同じ英語の名前、見出しのセルに日本語の説明をメモで付ける）**。以下は判断時の比較の記録として残す。

### 9.1 同期エラーの内容を記録（IndexedDB）に持つか（roadmap 7.14 要判断⑥・7.18 R-11 に関係）

**背景**：同期状態の画面（S-07・T-43）では「未送信件数・最終同期日時・エラー内容」を見られるようにします（requirements F-07）。

- 未送信件数：記録の `syncStatus`（`pending`・`error`）で数えられる（すでにある項目）。
- 最終同期日時：記録の `syncedAt` の一番新しい値で分かる（すでにある項目）。
- **エラー内容**（「合言葉が違います」「通信できませんでした」など）だけは、今の記録の項目にありません。どこに置くかを決める必要があります。

**記録に持たせる場合の手間**：記録に新しい項目（例 `syncError`）を足すと、requirements 6.1 の32項目が33項目になり、すべての記録に新しい項目を入れる**データの移し替え（DB の版を 1 → 2 に上げる作業）**が要ります（architecture 6.11）。そのときに起きうるのが **R-11**（PC などで古い版のアプリを別のタブで開いたままだと、新しい版の保存が「保存中」のまま終わらない不具合）で、版を上げる前に R-11 を直す（保存に見切り時間を設ける）必要があります。

| 案 | 内容 | よい点 | 困る点 |
|---|---|---|---|
| **A（推奨）** | **記録には持たない**。記録ごとの状態はこれまでどおり `syncStatus`（`pending`・`synced`・`error`）だけ。エラー内容は**端末の設定の保存場所（localStorage）に「最後のエラー」を1つだけ**持つ（いつ・何が起きたか・受け付けられなかった記録があればその件数と ID）。次に送信が成功したら消す | **DB の版を上げない**ので、R-11 は今までどおり後回しにできる。記録・CSV・シートの列（32列）が変わらない。エラーの多くは「通信できない」「合言葉が違う」「シートの見出しが違う」など**全件に共通の原因**なので、1つあれば足りる。アプリを開き直してもエラーが見える | 記録1件ずつの細かい理由は残らない（受け付けられなかった記録の ID は「最後のエラー」に入れるので、どの記録かは分かる）。requirements 6.3 に設定のキーを1つ足す（DB の作業ではない） |
| B | 記録に `syncError`（エラー内容）を足す | 記録ごとに理由が分かる | DB の版を上げる作業と、その前の R-11 の修正が要る。requirements 6.1・`TRADE_KEYS`・CSV（33列にするか除くか）・シートの列・T-44・テストをまとめて直す。移し替えの前に CSV の書き出しを案内する必要もある（architecture 6.11）。古い版を開いたままの別のタブは新しい DB を開けなくなる |
| C | 同期の記録用に別の保存場所（ストア `syncLog`）を作る | 記録（`trades`）の項目は変わらない。履歴も残せる | ストアを足すのも DB の版を上げる作業なので、B と同じく R-11 の修正が先に要る |
| D | どこにも保存しない（アプリを開いている間だけ覚える） | 一番簡単 | アプリを開き直すとエラー内容が消え、「失敗」の印（`error`）だけが残って理由が分からない |

**推奨：A**。理由は、①エラーの原因はほとんどが全件共通で、記録ごとに持つ価値が小さい、②DB の版を上げずに済むので、R-11 を直す作業もデータの移し替えの危険（architecture 6.11）も今は発生しない、③記録・CSV・シートの32列がそのままで、T-44 とシートの往復の前提が変わらない、の3点です。

- A を選んだ場合：localStorage のキー名は `syncLastError`（実際の保存キーは `fxnote:syncLastError`）を提案します。中身は「起きた日時・種類（通信・合言葉・シートの形・受け付けなかった記録 など）・画面に出す文・受け付けなかった記録の件数と ID（最大10件程度）」。**合言葉や Apps Script の URL は入れない**（画面の写真を人に見せても漏れないように）。
- 将来、記録ごとの理由がどうしても必要になったとき（例：受け付けられない記録が頻繁に出る）は、そのとき B か C に切り替え、R-11 を先に直します（roadmap 7.18 R-11 の「前倒しのきっかけ」）。

**判断してほしいこと**：A（推奨）・B・C・D のどれにするか。

### 11.3 要求の形（アプリ → Apps Script）

**送り方（T-40・T-41 の engineer 向け）**

```js
fetch(gasUrl, {
  method: 'POST',
  body: JSON.stringify(request), // headers は付けない（下の理由）
  redirect: 'follow',
  credentials: 'omit',
  cache: 'no-store',
});
```

- **`headers` を付けない**。本文が文字だと、ブラウザは `Content-Type: text/plain;charset=UTF-8` を付けて送る。これは CORS（別のサイトへの送信の制限）の「単純なリクエスト」にあたるので、事前の確認（プリフライト）が出ない。`application/json` にするとプリフライトが出て、Apps Script はそれに答えられず失敗する。
- Apps Script は応答を `script.googleusercontent.com` へ転送（リダイレクト）して返す。`redirect: 'follow'`（既定）で受け取る。CSP の `connect-src` に `https://script.google.com` と `https://script.googleusercontent.com` の両方が要る（architecture 14.3。T-40 の完了条件）。
- `sw.js` の fetch の処理は、この送信（別のサイトへの POST）をキャッシュに入れたり横取りしたりしないこと（T-40・T-41 で確認）。
- 応答はいつも **HTTP 200**（Apps Script は状態コードを変えられない）。成否は本文の `ok` と `error.code` で見る。

**本文（JSON）**

```json
{
  "app": "fx-trade-note",
  "v": 1,
  "token": "（設定画面の合言葉）",
  "action": "upsert",
  "records": [
    { "priceDecimals": 3, "values": { "id": "3f2b8c1e-6a0d-4e2f-9b7a-1c2d3e4f5a6b", "accountType": "real", "pair": "USD/JPY", "…": "…（32の見出しすべて）" } }
  ]
}
```

| 名前 | 型 | 必須 | 内容 |
|---|---|---|---|
| `app` | 文字 | ○ | いつも `fx-trade-note`。違えば `BAD_REQUEST` |
| `v` | 数値 | ○ | 要求の形の版。いまは `1`。違えば `UNSUPPORTED_VERSION` |
| `token` | 文字 | ○ | 設定画面の合言葉（`syncToken`）。前後の空白は保存の時点で取り除いてある前提 |
| `action` | 文字 | ○ | `ping`（接続テスト。**シートに何も書かない**）か `upsert`（記録を書く） |
| `records` | 配列 | `upsert` のとき○ | 1件ずつの記録。**1回に100件まで**（101件以上は `TOO_LARGE`）。0件なら何もせず `ok` |
| `records[i].values` | オブジェクト | ○ | 4.1 の**32の見出しすべて**をキーにした値（4.3 の作り方）。足りない・余分なキーがあれば、その記録は `rejected`。`imageIds` ではなく `imageCount` |
| `records[i].priceDecimals` | 数値 | 任意 | 価格の小数桁（`getPairSpec(pair).priceDecimals`：3 か 5）。無い・3 と 5 以外のときは「`pair` が `/JPY` で終われば 3、それ以外は 5」で補う |

**1件の値の決まり（Apps Script が確かめること：10.2 #3）**

| 列 | 受け付ける値 | 受け付けないとき（`reason`） |
|---|---|---|
| 文字の列（21列） | 文字だけ（未入力は空の文字 `""`。`null` は不可） | 文字でない → `BAD_TEXT`。50,000文字を超える → `TOO_LONG`（シートの1セルの上限） |
| 文字の列の先頭 | 先頭が `=` `+` `-` `@` タブ CR のものは、**`'` が付いているときだけ**受け付ける（`guardFormula` の結果。`'` で始まる文字はどれもそのまま） | 印のない `=` `+` `-` `@` タブ CR 始まり → `FORMULA`（5.4。印を付け直すことはしない） |
| `id` | UUID の形（英小文字・数字・ハイフンの36文字） | `BAD_ID` |
| 日時の列（`entryAt`・`exitAt`・`syncedAt`・`deletedAt`・`createdAt`・`updatedAt`） | 空か、固定形式25文字（`YYYY-MM-DDTHH:mm:ss+09:00`） | `BAD_DATETIME`。**`updatedAt` だけは空も不可** |
| 数値の列（11列） | 有限の数（JSON の数値）か `null` | 文字の `"150.1"`・真偽・`Infinity` など → `BAD_NUMBER` |

- 列の値の範囲（`side` が `buy`／`sell` かなど）は確かめない（シートは控えで、正しさはアプリが守る）。

### 11.4 応答の形（Apps Script → アプリ）

**どの応答にも付く項目**

| 名前 | 内容 |
|---|---|
| `app` | いつも `fx-trade-note`。**これがあれば「このアプリ用の Apps Script の答え」**（design 14.6.8 の T-5 との区別） |
| `v` | Apps Script 側の要求の形の版（いまは `1`） |
| `script` | コードの版（いまは `1.1.0`。オーナーがコードを貼り直したかの目印） |
| `action` | `ping`・`upsert`。**合言葉を確かめる前のエラー（`BAD_TOKEN` など）と `BAD_REQUEST` では `null`** |
| `ok` | `true`（処理した）／`false`（全体のエラー。`error` を見る） |

**接続テストの成功**

```json
{ "app": "fx-trade-note", "v": 1, "script": "1.1.0", "action": "ping", "ok": true,
  "sheet": { "name": "trades", "state": "ready" } }
```

- `sheet.state`：`ready`（準備済み）／`missing`（タブがまだ無い）／`empty`（タブが空）。**どれも成功**（`missing`・`empty` は最初の `upsert` か「シートを準備する」で準備される）。見出しが違うときは成功ではなく `HEADER_MISMATCH` を返す。

**書き込みの結果**

```json
{ "app": "fx-trade-note", "v": 1, "script": "1.1.0", "action": "upsert", "ok": true,
  "results": [
    { "id": "（1件目の id）", "result": "added" },
    { "id": "（2件目の id）", "result": "updated", "duplicate": true },
    { "id": "（3件目の id）", "result": "stale" },
    { "id": "（4件目の id）", "result": "rejected", "reason": "FORMULA", "column": "memo" }
  ],
  "counts": { "added": 1, "updated": 1, "stale": 1, "rejected": 1 } }
```

- **`results[i]` は `records[i]` に対応**（同じ順・同じ数）。アプリは `id` と並びの両方で照らし合わせられる。
- `result`：`added`（行を追加）／`updated`（上書き）／`stale`（シートの方が新しいので書かなかった）／`rejected`（受け付けなかった。`reason` と、列に関わるときは `column`）。
- `duplicate: true`：シートに同じ `id` の行が2つ以上あった（上の行を使い、ほかは触らない：6.1）。
- `rejected` の `id`：送られた `id` が文字ならそのまま（最大64文字）、文字でなければ `null`。
- **一部の記録が `rejected` でも、ほかの記録は書く**（`ok` は `true`）。

**全体のエラー**

```json
{ "app": "fx-trade-note", "v": 1, "script": "1.1.0", "action": null, "ok": false,
  "error": { "code": "BAD_TOKEN", "message": "合言葉が違います。" } }
```

- `error.message` は開発者ツールで見るための短い日本語。**アプリの画面の文は `error.code` で出し分ける**（design 14.6.8・9.15。`message` をそのまま画面に出さない）。
- `HEADER_MISMATCH` だけは、`error.column`（最初に違った列の文字。例 `C`）・`error.expected`（そこにあるべき見出し）・`error.actual`（実際の見出し。最大50文字）が付く。
- 全体のエラーのときは、**シートに何も書いていない**（`INTERNAL` だけは例外：11.5 の注）。

### 11.5 エラーコードの一覧

**全体のエラー（`ok: false` の `error.code`）**

| コード | 起きるとき | 合言葉の照合の前か | アプリでの扱い（10.3）の推奨 | 接続テストの文（design 14.6.8） |
|---|---|---|---|---|
| `BAD_REQUEST` | 本文が無い・JSON でない・`app` が違う・`action` が違う・`records` が配列でない | 前（`app` の確認まで）／後（`action`・`records`） | アプリの誤り。記録は `error`、`syncLastError` に残す | T-6 |
| `TOO_LARGE` | 本文が200万文字を超える／記録が101件以上 | 前／後 | アプリの送り方の誤り（1回の件数を減らす） | — （接続テストでは起きない） |
| `UNSUPPORTED_VERSION` | 要求の `v` が Apps Script の版と違う | 前 | 「Apps Script のコードを新しくしてください」の扱い。記録は `pending` のまま | T-6（分けるなら designer に） |
| `TOKEN_NOT_SET` | スクリプト プロパティの `SYNC_TOKEN` が無い・決まり（11.6）に合わない。**この間は誰の要求も通さない** | 前 | 設定の問題。記録は `error` か `pending` のまま | T-6（分けるなら designer に：11.10） |
| `BAD_TOKEN` | 合言葉が違う（無い・文字でない・1024文字を超えるものも含む） | — | 設定の問題。記録は `error` か `pending` のまま | **T-2** |
| `NO_SPREADSHEET` | Apps Script がスプレッドシートに付いていない | 後 | 設定の問題 | T-6 |
| `HEADER_MISMATCH` | タブ `trades` の1行目の A〜AF が4.1 の32の見出しと違う（列を足した・消した・並べ替えた・見出しを書き換えた、1行目が空なのに2行目以降に中身がある、など） | 後 | 設定の問題（オーナーがシートを直すまで同じ）。記録は `error` か `pending` のまま | T-6（分けるなら designer に） |
| `BUSY` | 10秒待ってもロックが取れない（ほかの書き込みが終わらない） | 後 | 一時的。記録は `pending` のまま、後で送り直す | — （ping はロックを使わない） |
| `INTERNAL` | Apps Script の中で想定外のエラー（Google 側の一時的な障害など）。**Google Sheets API の「サービス」が追加されていないときも `INTERNAL` で、`error.reason` が `SHEETS_API_NOT_ADDED`**（1.1.0 から。`ping` でも返すので接続テストで分かる。`upsert` では何も書かずに返す） | 後 | 一時的として扱い、`pending` のまま後で送り直す（続くなら `syncLastError` で知らせる）。`reason` が `SHEETS_API_NOT_ADDED` のときは設定の問題（オーナーがサービスを追加するまで同じ） | T-6 |
| `USE_POST` | ブラウザで URL を開いた（GET） | — | アプリからは起きない | — |

- **注（`INTERNAL`）**：書き込みの途中で失敗した場合、それまでの行は書かれている。アプリは全件を失敗として後で送り直してよい（`id` で上書きするので行は二重にならない）。
- 合言葉の照合の前に返すエラー（`BAD_REQUEST` の一部・`TOO_LARGE`・`UNSUPPORTED_VERSION`・`TOKEN_NOT_SET`・`BAD_TOKEN`）には、シートの状態などの情報を一切含めない。
- 「自動で送り直す」の止め方（設定の問題のときに何度も送らない、など）は T-42 で決める。sheets-integrator の推奨は「`BAD_TOKEN`・`TOKEN_NOT_SET`・`HEADER_MISMATCH`・`NO_SPREADSHEET`・`UNSUPPORTED_VERSION` は、設定（URL・合言葉）を変えたとき・アプリを開いたとき・『今すぐ同期』のときだけ送り直す」。

**1件ごとの受け付けない理由（`result: "rejected"` の `reason`）**

| コード | 内容 | `column` |
|---|---|---|
| `BAD_RECORD` | 記録がオブジェクトでない・`values` が無い | なし |
| `MISSING_COLUMN` | 32の見出しのどれかが無い | 無かった見出し |
| `UNKNOWN_COLUMN` | 32の見出しにないキーがある（`imageIds` を送った、など） | 余分なキー |
| `BAD_ID` | `id` が UUID の形でない | `id` |
| `BAD_TEXT` | 文字の列が文字でない（`null` を含む） | その列 |
| `TOO_LONG` | 文字が50,000文字を超える | その列 |
| `FORMULA` | 印（`'`）のない `=` `+` `-` `@` タブ CR で始まる | その列 |
| `BAD_DATETIME` | 日時の列が固定形式でない、`updatedAt` が空 | その列 |
| `BAD_NUMBER` | 数値の列が有限の数でも `null` でもない | その列 |

- 見る順は「記録の形 → 見出しがそろっているか → 余分なキー → 列の順に値」で、**最初に見つかった1つ**だけを返す。
- アプリは `rejected` の記録を `error` にし、`syncLastError` に件数と `id`（最大10件程度）を入れる（9.1 の決定）。ふつうは起きない（アプリの誤りでしか起きない）ので、起きたら engineer・sheets-integrator に知らせる案内でよい。

**接続テストの結果の見分け方（T-40 の engineer 向け。design 14.6.8 の文の出し分け）**

| 順 | 条件 | 出す文 |
|---|---|---|
| 1 | `fetch` が例外で失敗し、`navigator.onLine` が `false` | T-1（オフライン） |
| 2 | 20秒で打ち切った | T-4（時間切れ） |
| 3 | `fetch` が例外で失敗した（上以外。デプロイしていない・「アクセスできるユーザー」が「全員」でない〔Google のログイン画面へ転送され、CORS で読めない〕・URL の誤り など） | T-3（届かない） |
| 4 | 応答の本文が JSON として読めない、または `app` が `fx-trade-note` でない（`doPost` の無い古いコード・別の Apps Script の URL など） | T-5（このアプリ用ではない） |
| 5 | `ok: true` かつ `action: "ping"` | T-OK |
| 6 | `error.code` が `BAD_TOKEN` | T-2（合言葉が違う） |
| 7 | それ以外の `error.code`（`TOKEN_NOT_SET`・`HEADER_MISMATCH`・`NO_SPREADSHEET`・`UNSUPPORTED_VERSION`・`INTERNAL`・`BAD_REQUEST`） | T-6（Apps Script 側のエラー）。分けて出すかは designer の判断（11.10） |

- 応答の文字・`error.message` は画面に出さず、開発者ツールにだけ出す（design 14.6.8）。**要求の本文（合言葉を含む）は `console` に出さない**。

### 11.6 合言葉の決まりと照合

| 項目 | 決めたこと |
|---|---|
| **最低の文字数** | **12文字**（design 14.6.8 の K-2 の仮の値 8文字から変更：11.10） |
| 最大の文字数 | 128文字 |
| 使える文字 | **半角の英字・数字・記号**（ASCII の表示できる文字。`!` から `~` まで）。**空白・全角の文字・改行は使えない** |
| 置き場所 | Apps Script の「スクリプト プロパティ」の `SYNC_TOKEN`。メニュー「合言葉を設定する」で入れる（決まりに合わないものは保存しない。前後の空白・改行は取り除く）。Apps Script の画面の「プロジェクトの設定（歯車）→ スクリプト プロパティ」で直接入れてもよいが、その場合も決まりに合わないと `TOKEN_NOT_SET` になる |
| 書かない場所 | コード・シート（値・メモ）・ログ・応答・メニューの表示（「設定済み」とだけ出す）のどこにも出さない |
| 照合の方法 | 届いた合言葉と保存した合言葉を、それぞれ **SHA-256 の要約（いつも32バイト）**にしてから、32バイトを**最後まで全部比べてから**一致・不一致を答える。途中で打ち切らないので、「何文字目まで合っていたか」で答えの速さが変わらない（時間差から合言葉を推測されにくい）。届いた合言葉が文字でない・1024文字を超えるときは空として扱う（必ず不一致） |
| 照合の前 | 本文の形（`app`・`v`）を確かめたあと、**シートには一切触らずに**照合する。合言葉が違えば、シートの状態も含めて何も返さない |

**12文字にした理由**

- URL（とても長く推測できない）が1つ目の鍵、合言葉が2つ目の鍵。合言葉は「URL が漏れたとき（画面の写真・共有など）にも書き込ませない」ための守りなので、**短い単語（`password` など）や誕生日だけの合言葉を入れられないようにする**最低限の長さとした。
- 入力は iPhone の「ペースト」が前提（design 14.6.12）なので、長くしても手間は変わらない。手順書（T-39）では **20文字以上の、意味のない文字の並び**（パスワード管理アプリや iPhone の「強力なパスワード」で作ったものなど）を勧める。
- 全角を使えなくしたのは、iPhone とパソコンで同じに見えて中身の違う文字（全角／半角、濁点の付け方の違い）が混ざって「合っているのに違う」と言われるのを避けるため。

**しないこと**

- 何回も間違えたら止める仕組み（ロックアウト）は入れない。URL を知った第三者が、わざと間違えてオーナーの同期を止められてしまうため。長さと照合の遅さ（Apps Script は1回の応答に1秒以上かかる）で守る。

### 11.7 書き込みの手順（10.2 の実装）

`upsert` を受けたときの流れ（`doPost` → `handleUpsert_` → `upsertRecords_`）：

1. 本文の形・版を確かめる → 合言葉を照合する（11.6）。
2. `records` の数を確かめる（100件まで）。0件なら何もせず `ok`。
3. **ロック**（`LockService` のスクリプトのロック）を最大10秒待って取る。取れなければ `BUSY`。以下はロックの中。
4. タブ `trades` が無ければ作る。空なら初期設定（10.2 #1：見出し32列を `@` の書式で書く・見出しのセルに日本語のメモ・1行目を固定・A2:AF の最後の行まで「`=$AD2<>""` なら文字を灰色（`#8e8e93`）」の条件付き書式）。新しいタブは26列（A〜Z）しかないので、AF 列まで列を足す。
5. **1行目の A〜AF を毎回確かめる**（10.2 #2）。違えば何も書かずに `HEADER_MISMATCH`（AG 列より右の見出しは見ない）。
6. A 列（`id`）と AF 列（`updatedAt`）を2行目から最後まで読み、`id` → 行の表を作る（同じ `id` が2つあれば上の行。下の行は `duplicate` として覚える）。
7. 記録を1件ずつ：値を確かめる（11.3）→ 行が無ければ**最後の行のすぐ下**に追加（どの列にも中身がない行。行が足りなければ足して、灰色の条件付き書式の範囲も広げる）／あれば `updatedAt` を文字のまま比べ、**届いた方が古いときだけ書かない**（等しい・新しいなら上書き。シートの値が固定形式でなければ上書き）。
8. 書くときは、**その行の A〜AF の表示形式を先に設定し（文字は `@`、数値は 5.3 の形式、価格は `priceDecimals` で行ごと）、そのあと値を書く**。`null` は空のセル。A〜AF より右には書かない。
9. 書き終えたら確定させ（`SpreadsheetApp.flush`）、ロックを外し、結果を返す。

- 日時は Apps Script で作らない・日付の値に直さない（10.2 #5）。シートの `syncedAt` はアプリが送った「送る時刻」（6.3）。
- オーナーが足したほかの条件付き書式は消さない（自分で付けた灰色の規則だけを入れ替える）。
- `ping` は 1・2 のあと、タブの状態と見出しを**読むだけ**（タブを作らない・ロックを使わない）。

**書き込みの方式（5.2 の方式 C に決定。2026-10-26・1.1.0）**

- `gas/Code.gs` の先頭近くの `const USE_SHEETS_API = true;`（1.1.0 からの既定）で、8 の値の書き込みが「Google Sheets API の読み替えなし（RAW）」になる。表示形式の設定は方式 A と同じで、行ごとに「表示形式 → 確定（`SpreadsheetApp.flush`）→ `Sheets.Spreadsheets.Values.update`（`valueInputOption: 'RAW'`）」の順に書く。
- このため、Apps Script の画面の左の「サービス ＋」から **Google Sheets API** を追加しておく（識別子は `Sheets` のまま。12.3 の 2-3）。追加し忘れたときは：
  - `ping`・`upsert` は `INTERNAL`（`error.reason`＝`SHEETS_API_NOT_ADDED`）を返す。`upsert` は何も書かない（タブも作らない）。
  - 「書き込みの自己テスト」は、テストを始めずに「Google Sheets API が追加されていません」と出して止まる。
  - 「設定を確認する」に「書き込みの方式：Sheets API（RAW）※「サービス」に Google Sheets API が追加されていません」と出る。
- Sheets API の許可は、SpreadsheetApp と同じ「スプレッドシートの参照・編集…」の範囲で、新しい種類の許可は増えない見込み（12.5）。
- `false`（方式 A）は比較のために残してある。本物では `'` の印が消えるので使わない（5.5）。
- 1行ごとに API を1回呼ぶので、方式 A より1行あたりの時間が長くなる。1回に送る件数（T-41・T-42 で決める。13.2 の推奨は20件程度から）は、iPhone からの送信で応答の時間を測って決める。

### 11.8 5.5 のテスト送信（自己テスト）の手順と結果

**本物の Google の環境でしか確かめられない**ため、T-39（手順書）・T-40（iPhone での接続テスト）のときに、オーナーの環境で次の順に確かめます。結果はこの節の表に記録します。

**手順（オーナーと一緒に行う。12章にも同じ流れを書く）**

1. `gas/Code.gs` を貼り付けて保存したあと、スプレッドシートを開き直す（メニュー「FXトレード記録」が出る）。

> - アプリの接続テストで「Apps Scriptでエラーが起きました。手順書の『シートの準備』を確認してください。」と出たときは、この手順のあとで 12.13 ① の「設定を確認する」の表を見てください。

### 12.5 手順4：初回の承認

スクリプトが自分のスプレッドシートを操作するには、最初に1回だけ、Google の許可（承認）が要ります。次の順に画面が出ます（順番や言葉が少し違うことがあります）。

1. 「承認が必要です」→「**OK**」（表示が違う場合は「続行」「権限を確認」）。
2. アカウントを選ぶ画面 → **自分のアカウント**を選ぶ。
   - 小さな別の窓で開きます。窓が出ないときは、ブラウザの「ポップアップをブロックしました」の表示から許可する。
3. 「**このアプリは Google で確認されていません**」の画面 → 左下の「**詳細**」（表示が違う場合は「詳細を表示」）を押す → 下に出る「**FXトレード記録 同期（安全ではないページ）に移動**」を押す。
4. 「FXトレード記録 同期 が Google アカウントへのアクセスをリクエストしています」の画面 → 許可の内容（下の表）を見る →「**許可**」（表示が違う場合は「続行」）。
   - 項目ごとのチェック欄が出たときは「**すべて選択**」にしてから進む。チェックを外すと動きません。
   - **チェックを入れずに「続行」を押すと**、実行ログに「警告　このプロジェクトを実行するには、ご利用の Google アカウントへのアクセスを許可する必要があります。再試行して、許可してください。」と出て止まります（2026-10-26 オーナーの環境で確認）。その場合は、もう一度「▶ 実行」（またはメニューの「シートを準備する」）を押し、承認の画面で「**すべて選択**」にチェックを入れてから「続行」を押してください。
5. 元の画面に戻ったら、手順3の4に戻って、もう一度「シートを準備する」を押す。

**「確認されていません」「安全ではないページ」の意味と、進んでよい理由**

- Google は、たくさんの人に配るアプリを審査（確認）しています。**自分で作って自分だけが使うスクリプトは審査の対象外**なので、いつもこの表示になります。
- 「安全ではない」は「Google が中身を調べていない」という意味です。危険と判定されたわけではありません。
- このスクリプトは、①自分のリポジトリの `gas/Code.gs` を自分で貼ったもの、②動くのは自分のアカウントの中だけ、③外部へデータを送る処理が無い、の3点から、進んでかまいません。
- **ほかの人から渡されたスクリプトや、出どころの分からないスクリプトでは、この画面で進まないでください。** 進んでよいのは、中身を自分で用意したスクリプトのときだけです。

**許可を求められる内容（見込み）**

| 表示（目安） | 何のために使うか |
|---|---|
| Google スプレッドシートのすべてのスプレッドシートの参照、編集、作成、削除 | タブ「trades」に行を書くため。言葉は「すべて」ですが、コードが触るのは**このスクリプトを付けたスプレッドシートだけ**です |
| Google アプリケーション内でのプロンプトやサイドバーの表示 | メニュー・合言葉の入力欄・結果の窓を出すため |

- 手順2で追加した Google Sheets API も、1つ目と同じ「スプレッドシートの参照、編集…」の許可で動きます（新しい種類の許可は増えない見込み）。同じ内容が2回出たり、まとめて1つになったりすることがあります。
- これ以外（Gmail・Google ドライブ・カレンダー・「外部サービスへの接続」など）が出たら、**許可せずに止めて知らせてください**。貼ったコードが `gas/Code.gs` と違う可能性があります。

**できたことの確かめ方**

- もう一度「シートを準備する」を押したとき、承認の画面が出ずに「準備ができています」と出る。

承認をやり直したい・取り消したいとき → 12.13 ⑦。

### 12.6 手順5：合言葉を作って設定する

合言葉は、ウェブアプリの URL を知った人が勝手に書き込めないようにするための鍵です（理由は 12.8）。

**合言葉の決まり**（合わないと保存されません）

- **12〜128文字**。**半角の英字・数字・記号だけ**。空白・全角の文字は使えない。
- おすすめは **20文字以上の、意味のない文字の並び**。単語・名前・誕生日・ほかで使っているパスワードは使わない。
- 覚える必要はありません（入力はコピーとペースト）。そのかわり、**安全な場所に1か所だけ保存**します。

**5-1 iPhone の「パスワード」アプリで作る（おすすめ）**

1. iPhone の「**パスワード**」アプリを開く（iOS 18 以降）。
2. 「＋」（新規）を押す。
3. 「Webサイトまたはラベル」に「FXトレード記録 合言葉」などと入れる。ユーザ名は空でよい（必須なら「fx-sync」など）。
4. 「パスワード」の欄を押す。キーボードの上などに「**強力なパスワード**」の候補が出たら、それを選ぶ（表示が違う場合は、自動で作られたパスワードの候補に相当するもの）。
   - 英字と数字の6文字を3つ、ハイフンでつないだ **20文字**ができます（例の形：`xxxxxx-xxxxxx-xxxxxx`）。この形は決まりに合います。
5. 「**保存**」（表示が違う場合は「完了」）。

- 候補が出ないとき：PC のブラウザのパスワード作成機能（Chrome の「パスワードを生成」など）や、パスワード管理アプリで作ってもかまいません。
- 自分で考える場合は、英字の大文字・小文字と数字を混ぜて20文字以上に。
- 見間違えやすい文字（`l` と `I`、`0` と `O`）を手で打ち写すのは避け、コピーとペーストで扱ってください。

**5-2 Apps Script に設定する（PC）**

1. 合言葉を PC に移す（方法は 12.9 の表。Mac なら「パスワード」アプリが同期されています）。
2. スプレッドシートのメニュー「FXトレード記録」→「**合言葉を設定する**」。
3. 入力欄に合言葉を貼り付けて「**OK**」。
   - この欄は伏せ字になりません。人に画面を見られていないときに行ってください。
4. 「合言葉を保存しました。…」と出たら「OK」。

**できたことの確かめ方**

- メニュー「FXトレード記録」→「**設定を確認する**」で「**合言葉：設定済み**」と出る（合言葉そのものは表示されません）。
- 「決まりに合っていないため、保存していません」と出たら、空白・全角が混ざっていないか、12文字以上あるかを確かめて、入れ直す。

> - 「合言葉を設定する」をもう一度行うと、前の合言葉は新しいものに置き換わります。そのときはアプリの合言葉も同じものに変えてください。
> - 合言葉を変えても、デプロイ（手順7）のやり直しは要りません。

### 12.7 手順6：書き込みの自己テストと報告

本物の Google のシートで、文字や数値が意図どおりに書けるかを確かめます。**開発の環境では確かめられない部分です。** 2026-10-26 の1回目（古いコード）で、先頭の `'` が消える問題が見つかり、書き込みの方式を方式 C（Google Sheets API）に切り替えました（5.5）。今のコード（1.1.0）で、すべて OK になることを確かめます。
テストはテスト用のタブ「**selftest**」に書きます。記録用のタブ「trades」には触りません。

**6-1 自己テストを動かす**

1. メニュー「FXトレード記録」→「**書き込みの自己テスト（テスト用のタブ）**」を押す。
2. 10秒ほどで「書き込みの自己テスト」の結果の窓が出る。
3. **窓のスクリーンショットを撮る**（合言葉や URL は写りません）。入りきらないときは2回に分けて撮る。
4. 「OK」で閉じる。

**窓の見るところ**

- **1行目**
  - 「**すべて期待どおりでした（19項目）。**」→ 成功。
  - 「19項目中 ○項目が期待と違いました。…」→ NG あり。「NG」で始まる行と、その行の「（実際：…）」を報告に入れる。
  - 「（18項目）」のとき → 合言葉が未設定。手順5をやり直してから、もう一度。
  - 「Google Sheets API が追加されていません」と出たとき → 12.3 の 2-3 でサービスを追加し、もう一度。
- **2行目以降**：1行ずつ「OK」か「NG」で始まる（合言葉の照合、8件を追加した、#1〜#12、上書きなどの4項目、前半の8行は変わっていない）。

**6-2 CSV に書き出して確かめる**

1. 画面の下の「**selftest**」のタブを選ぶ（このタブを表示した状態で書き出す）。
2. 「**ファイル**」→「**ダウンロード**」→「**カンマ区切り形式（.csv）**」。「（スプレッドシートの名前） - selftest.csv」がダウンロードされる。
3. ファイルを**メモ帳（Windows）かテキストエディット（Mac）で開く**。
   - Windows：ファイルを右クリック →「プログラムから開く」→「メモ帳」。
   - Mac：ファイルを右クリック →「このアプリケーションで開く」→「テキストエディット」。
   - **Excel や Numbers では開かない**でください。開いた時点で日時や数字の形が変わって見え、確かめになりません（7.1）。
4. 検索（Ctrl＋F／⌘＋F）で、下の表の文字を1つずつ探す。**前後の `,`（半角のカンマ）がある文字は、カンマも含めて**探してください（ほかの場所の文字と取り違えないため）。

| 記号 | 探す文字 | 期待 |
|---|---|---|
| ア | `2026-10-15T21:30:12+09:00` | 見つかる（`2026/10/15` のような形になっていない） |
| イ | `,3/4,` | 見つかる（日付の形に変わっていない） |
| ウ | `,001,` と `,1e3,` | どちらも見つかる（`1`・`1000` に変わっていない） |
| エ | `'=1+1` | 見つかる（先頭の `'` が付いたまま） |
| オ | `''=x` | 見つかる（`'` が2つ） |
| カ | `'普通` | 見つかる（先頭の `'` が付いたまま） |
| キ | `""引用符""` | 見つかる。その行の終わりが `"カンマ,と""引用符""と`、次の行の始まりが `改行"` |
| ク | `,150.100,` | 見つかる（`150.1` ではなく小数3桁） |
| ケ | `,1.08510,` | 見つかる（小数5桁） |
| コ | `,-37.7,-1885,` | 見つかる（pips と損益が続けて並ぶ） |
| サ | `,,0,auto,` | 見つかる（空の pips のあとに、損益の `0` が空欄ではなく `0` で出る） |
| シ | `,1500,` と `,10000,` | どちらも見つかる（`1,500`・`10,000` のような3桁区切りが無い） |
| ス | `2026-10-16T09:06:00+09:00` | 見つかる（削除の印の日時。同じ行の更新日時と同じ値なので、2か所で見つかります） |

- `TRUE`・`50%`（#3）と UUID（#12）は、CSV の文字では見分けがつかないので、6-1 の窓だけで確かめます。

**6-3 報告する（ここで一度止めて連絡してください）**

次の形で送ってください。スクリーンショット（6-1）の添付だけでもかまいません。

```
【自己テストの報告】
① 結果の窓の1行目：
② NG の行（あれば、その行をそのまま。なければ「なし」）：
③ CSV の確認 ア〜ス：全部見つかった ／ 見つからなかった記号と、代わりに見えた形：
④「設定を確認する」の表示：合言葉＝　／ タブ「trades」＝　／ 書き込みの方式＝　／ コードの版＝
```

- 報告を受けたら、sheets-integrator が 11.8 の表（方式 C の列）に結果を記録します。
- **すべて OK なら、そのまま手順7に進んでかまいません。**
- **NG があったときは、手順7に進まずに連絡を待ってください。** 直したコードへの貼り直しが必要になることがあります。
- 報告が済んだら、タブ「selftest」は消してかまいません（タブを右クリック →「削除」）。残しても同期には影響しません。ダウンロードした CSV も消してかまいません（テスト用の値だけで、記録は入っていません）。

### 12.8 手順7：ウェブアプリとして公開する（デプロイ）

1. Apps Script の画面の右上の「**デプロイ**」→「**新しいデプロイ**」。
2. 「種類の選択」の横の歯車のアイコン →「**ウェブアプリ**」。
3. 次のように選ぶ。

| 項目 | 選ぶもの |
|---|---|
| 説明 | 「1.1.0」など（空でもよい。バージョンの見分けに使う） |
| 次のユーザーとして実行 | **自分**（自分のメールアドレスが出る） |
| アクセスできるユーザー | **全員** |

> 「アクセスできるユーザー」には「自分のみ」「Google アカウントを持つ全員」「全員」があります。**必ず「全員」**を選んでください。「Google アカウントを持つ全員」はよく似ていますが別のもので、アプリからの送信が届きません。

4. 「**デプロイ**」を押す。「アクセスを承認」と出たら、手順4と同じように進める。
5. 結果の画面の「ウェブアプリ」の「**URL**」の下の「**コピー**」を押す。
6. 「**完了**」。

**URL の形**

- `https://script.google.com/macros/s/（長い英数字）/exec`。**最後が `/exec`** であること。
- 最後が `/dev` の URL（「デプロイをテスト」で出るもの）は使えません。
- URL は「デプロイ」→「**デプロイを管理**」で、いつでも見てコピーできます。

**できたことの確かめ方：URL をブラウザで開く**

1. コピーした URL を、ブラウザの新しいタブのアドレス欄に貼って開く。
2. 次のような文字だけのページが出れば、公開できている。
   `{"app":"fx-trade-note","v":1,"script":"1.1.0","action":null,"ok":false,"error":{"code":"USE_POST","message":"このURLはFXトレード記録アプリからの送信専用です（…）。"}}`
   - `"ok":false` や `error` と出ますが、**これで正常**です。ブラウザで開くと「送信専用です」と答える作りです。
3. Google のログイン画面や「ファイルを開くことができません」が出たら、「アクセスできるユーザー」が「全員」になっていません（12.13 ②）。
4. 開いたあと、アドレス欄は `script.googleusercontent.com` で始まる別のアドレスに変わります。**アドレス欄の文字はコピーしないでください。** アプリに入れるのは、上の5で「コピー」を押した（「デプロイを管理」にも出る）`/exec` の URL です。

**「全員」を選ぶ理由と、合言葉がその守りになること（大事）**

- アプリは Google にログインせずに記録を送ります。そのため、**「アクセスできるユーザー」は「全員」にする必要があります**。
- 「全員」にすると、**URL を知っている人なら誰でも、この URL に送信できる**状態になります。
- そこで Apps Script は、送信のたびに**合言葉を照合し、合わなければシートに何もせずに断ります**（シートの状態も答えません：11.6）。URL が1つ目の鍵、**合言葉が2つ目の鍵**です。
- 仮に URL と合言葉の両方を知られても、できるのは「trades」タブへの行の追加・上書きだけです。**シートの中身を読み出すことや、ほかのファイルを触ることはできません。** 端末の中の記録（正のデータ）にも影響しません。それでも控えを荒らされるおそれがあるので、URL と合言葉は人に教えないでください（12.14）。
- 「次のユーザーとして実行：自分」は、シートに書く権限を自分のものにする設定です。送信してきた人に、自分の Google アカウントの権限が渡るわけではありません。
- 知られたかもしれないとき → 12.13 ⑨。

### 12.9 手順8：URL と合言葉を iPhone に移す

アプリに入れるのは iPhone です。PC でコピーした URL（と、PC で作った場合は合言葉）を iPhone に移します。

| PC の種類 | おすすめの方法 |
|---|---|
| Mac | ①**ユニバーサルクリップボード**：Mac と iPhone が同じ Apple アカウントで、どちらも Wi-Fi・Bluetooth・Handoff がオンなら、Mac でコピー → iPhone でそのままペーストできる。②**AirDrop**：テキストエディットに貼って、自分の iPhone に送る。③**「パスワード」アプリ**：合言葉の項目の「メモ」に URL を貼って保存（iPhone に同期される） |
| Windows | ①**自分宛てのメール**：Gmail で自分のアドレスに送り、iPhone のメールで開いてコピー。②**iCloud のメモ**：ブラウザで icloud.com の「メモ」に貼り、iPhone の「メモ」アプリで開く。③「iCloud for Windows」を入れているなら「パスワード」アプリ |

**保存先は1か所に（おすすめ：iPhone の「パスワード」アプリ）**

- 手順5で作った合言葉の項目の「**メモ**」に、URL も入れておく。機種変更やアプリの入れ直しのときに、すぐ入れ直せます。
- 「パスワード」アプリは、Face ID などで守られた、暗号化された保存場所です。

**注意**

- 人に見える場所を通さない：家族・友人とのトーク、グループ、SNS の下書き、共有のメモ・共有フォルダは使わない。
- 自分宛てのメールやメモを使ったときは、**アプリに入れ終わったら消し、「ゴミ箱」「最近削除した項目」からも消す**。
- スクリーンショットで移さない（写真に残り、共有されやすいため）。
- URL は1文字欠けても届きません。手で打たず、必ずコピーとペーストで。

**できたことの確かめ方**

- iPhone で URL をペーストできる状態になっている（正しい形かどうかは、手順9でアプリが確かめます）。

### 12.10 手順9：アプリに入力して接続テスト（T-40 の完成後）

> この手順は、アプリの設定画面に「スプレッドシート同期」ができてから（T-40）行います。画面の名前は今の設計（design 14.6.8）のもので、完成時に少し変わることがあります。

1. アプリを開き、下の「**設定**」タブ →「**スプレッドシート同期**」のグループ。
2. 「**Apps Script URL**」の欄を押し、長押し →「**ペースト**」。欄の外を押すと「設定を保存しました」と出る。
3. 「**合言葉**」の欄を押し、ペースト。「表示」を押すと中身を確かめられる（確かめたら「隠す」）。欄の外を押すと「設定を保存しました」と出る。
   - キーボードの上に「強力なパスワード」の候補が出ても、**選ばないでください**（別の文字に置き換わります）。
4. 「**接続テスト**」を押す。「確認中」のあと、
   - 「**接続できました（時:分）**」→ 完了です。
   - それ以外の文 → 12.13 ①。
5. 移すのに使ったメール・メモを消す（12.9）。

- 接続テストは、シートに何も書きません。成功しても、それだけでは記録は送られません（記録を送る仕組みは T-41 以降）。

### 12.11 iPhone だけで設定する場合

PC がない場合に、できる範囲を書きます。ただし画面が小さく操作しにくいので、**PC での作業をおすすめします**（この方法は iPhone の実機でまだ試していません）。

**② ブラウザで URL を開くと、ログイン画面や「ファイルを開くことができません」になる**

- 「アクセスできるユーザー」が「全員」になっていません。
- 「デプロイを管理」→ 鉛筆 →「アクセスできるユーザー」を「**全員**」→「バージョン」を「新バージョン」→「デプロイ」。
- 選べないとき：「全員」が一覧に無いなら、会社・学校のアカウントの可能性があります。個人の Google アカウントで、手順1からやり直してください。編集で変えられないときは「新しいデプロイ」で作り直し、新しい URL をアプリに入れます。

**③ 合言葉を忘れた・分からなくなった**

- いちばん確実なのは、**新しい合言葉に作り直す**ことです：手順5（作る →「合言葉を設定する」）→ アプリの合言葉の欄にも新しいものを入れる → 接続テスト。デプロイのやり直しは要りません。
- 今の合言葉を見たいだけなら、Apps Script の画面の「プロジェクトの設定」（歯車）→「スクリプト プロパティ」の `SYNC_TOKEN` に出ています（自分のアカウントでしか見られません）。
- 合言葉が合わない間、シートへの送信は失敗しますが、**記録は端末に残っています**。シートへの送信の失敗で記録が消えることはありません。

**④ URL を忘れた**

- 「デプロイ」→「デプロイを管理」→ アクティブなデプロイの「ウェブアプリ」の URL →「コピー」。
- アプリの設定画面（手順9のあと）にも入っています。

**⑤ メニュー「FXトレード記録」が出ない**

- スプレッドシートを読み込み直す（コードを保存したあとは、読み込み直さないと出ません）。
- Apps Script の画面で保存できているか（「保存していない」印が無いか）。
- スプレッドシートの「拡張機能 → Apps Script」で開いたプロジェクトに貼ったか（別のプロジェクトに貼っていないか）。
- iPhone のスプレッドシートのアプリでは出ません（12.11）。

**⑥ タブ「trades」の見出しを変えてしまった**

- 1行目を元の見出し（4.1 の32個。A 列の `id` から AF 列の `updatedAt` まで）に戻せば直ります。どの列が違うかは「設定を確認する」に出ます。
- 戻せないときは、タブの名前を「trades-old」などに変えて退避し、「シートを準備する」で新しい「trades」を作ります。新しいタブには、次にアプリで変更した記録から書かれます（全件を送り直す操作は今後検討：6.4）。

**⑦ 承認をやり直したい・取り消したい**

- 承認の途中で「キャンセル」した・窓を閉じた：もう一度メニューを押せば、承認の画面がまた出ます。
- 承認の画面で「エラーが発生しました」「現在ファイルを開くことができません」などと出る：複数の Google アカウントにログインしていることが原因のことが多いです。シークレット ウィンドウなどで、使うアカウント1つだけでログインしてやり直してください。
- 取り消したい：Google アカウントの管理画面（`https://myaccount.google.com`）→「**セキュリティ**」→「**サードパーティ製のアプリとサービスとの接続**」（表示が違う場合は、Google アカウントにアクセスできるアプリの一覧に相当するもの）→「FXトレード記録 同期」→「**アクセス権を削除**」（表示が違う場合は「接続をすべて削除」）。
  - 取り消すと、もう一度承認するまで、アプリからの送信も書き込めなくなります。使い直すときは、メニューを押して承認し直します。

**⑧ 自己テストが途中で止まる・エラーの帯が出る**

- Apps Script の画面の左の「**実行数**」を開き、いちばん上の `runSelfTest` の行を押す。出たエラーの文をスクリーンショットで知らせてください。

**⑨ URL や合言葉を人に知られたかもしれない**

- 合言葉だけ：手順5で新しい合言葉にし、アプリにも入れる。
- URL も：「デプロイ」→「新しいデプロイ」で新しい URL を作り（手順7）、アプリの URL を入れ替える。そのあと「デプロイを管理」で古いデプロイを選び「**アーカイブ**」する（古い URL は使えなくなる）。
- タブ「trades」に見覚えのない行が無いか見る。シートは控えで、正のデータは端末にあります。

### 12.14 やってはいけないこと・してよいこと

**やってはいけないこと**

- **URL と合言葉を人に教えない。SNS・チャット・掲示板に貼らない。**
  - 画面のスクリーンショットを人に見せるときは、アプリの設定画面（合言葉を「表示」している状態）、Apps Script の「デプロイを管理」「スクリプト プロパティ」が写っていないか確かめる。
- **URL と合言葉を GitHub（リポジトリ・Issue）やコードに書かない。** リポジトリは公開されていて、誰でも読めます。
- **タブ「trades」の1行目（見出し）を書き換えない。**
- **A〜AF 列を並べ替えない・足さない・消さない**（列と列の間に列を入れることも含む）。
  - Apps Script は書き込むたびに見出しを確かめ、**1つでも違うと書き込みを止める作り**です（記録を違う列に書かないため）。止まっている間、シートへの控えは増えません（記録は端末に残ります）。
- **タブ「trades」の名前を変えない。**
- A〜AF のセルを手で書き換えない・行を消さない。直すときはアプリで直す（シートの内容はアプリに戻りません：6.4）。
- ほかの人から渡されたスクリプトを、このスプレッドシートに貼らない。
- 更新のたびに「新しいデプロイ」を作らない（URL が変わる。更新は 12.12）。

**してよいこと**

- 行の並べ替え・フィルタ・列の幅・文字の色を変える。Apps Script は `id` で行を探すので問題ありません（並べ替えるときは1行目の見出しを含めない）。
- 集計や見やすい表は、**別のタブ**（「シート1」など）で作る。例：`=QUERY(trades!A:AF, …)`、ピボットテーブル。
- AG 列より右に、自分のメモ用の列を足す（ただし、別のタブの方がおすすめ）。
- 削除済みの記録（`deletedAt` に日時がある行）は灰色の文字になります。この条件付き書式は消さない方が見分けやすいです。

**シートを CSV で書き出す（バックアップ・アプリへの取り込み用）**

1. タブ「**trades**」を選ぶ。
2. 「ファイル」→「ダウンロード」→「**カンマ区切り形式（.csv）**」。いま表示しているタブだけが書き出されます。
3. アプリの「CSV を読み込む」（T-44）では、**ダウンロードしたファイルをそのまま**読み込んでください。Excel などで開いて保存し直したファイルは、日時や数字の形が変わり、読み込めないことがあります（7.1）。
4. シートの CSV には、削除済みの記録もいつも入っています（アプリには削除済みのまま取り込まれます）。画像は入っていません（8章）。
