## 1. 目的

FXのデモトレード・本番トレードを、**エントリー時**と**決済時**の2回に分けてスマホで素早く記録し、後から一覧・分析で振り返ることで、**自分の勝ちパターン・負けパターンに気づけるようにする**。

- 記録の手間を最小にし、「記録が続かない」問題をなくす
- デモと本番を明確に分けて管理し、混同による判断ミスを防ぐ
- 端末内に安全に保存し、Googleスプレッドシートにも自動で控えを残す
- **無料**で運用できる

> 本アプリは**記録・振り返り用のツール**です。売買の推奨や「この手法で勝てる」といった投資助言にあたる機能・文言は入れません。

## 2. 想定ユーザー

| 項目 | 内容 |
|---|---|
| 人物像 | 仕事の合間や夜にスマホでFXをする個人トレーダー（＝オーナー本人。当面は1人で使う） |
| 運用 | デモ口座と本番口座の両方を運用中 |
| 心理状態 | エントリー直後は気持ちが高ぶっており、細かい入力は面倒に感じる |
| 振り返り | 週末などにまとめて過去トレードを見返し、負けパターンを知りたい |
| 端末 | スマホ中心（片手操作）。振り返りはPCでスプレッドシートを見ることもある |

## 3. 利用シーン

| # | シーン | 期待すること |
|---|---|---|
| 1 | **エントリー直後**：業者アプリで注文した直後に、ホーム画面のアイコンからアプリを開いて記録 | 必須項目だけなら**30秒以内**で保存できる。日時は自動入力、デモ/本番・通貨ペアは前回値 |
| 2 | **決済直後**：保有中（open）の記録を開き、決済価格を入れる | pips・損益が自動計算され、ワンタップで「決済済み（closed）」になる |
| 3 | **チャートを残したい時**：スクショを添付 | 撮影済み画像を選ぶだけで添付。自動で縮小して容量を節約 |
| 4 | **週末の振り返り**：一覧で「本番だけ」「USD/JPYだけ」「負けトレードだけ」などに絞り込む | 条件で素早く探せる。詳細でメモ・画像・感情を見返せる |
| 5 | **分析**：勝率や累積損益の推移、切り口別（通貨ペア・感情など）の成績を見る | デモ/本番を分けて集計。件数が少ない切り口は「データ不足」と表示 |
| 6 | **電波が悪い場所**：地下鉄などオフラインで記録 | 端末内に保存でき、オンライン復帰後にスプレッドシートへ自動送信 |
| 7 | **機種変更・万一の備え**：CSVでバックアップを書き出す／読み込む | データを失わない |

## 4. 用語の説明（このドキュメントで使う言葉）

| 用語 | 一言説明 |
|---|---|
| PWA | Progressive Web App。Webサイトなのにスマホのホーム画面に追加でき、アプリのように全画面・オフラインで動く仕組み |
| MVP | Minimum Viable Product。「最小限これだけあれば実際に使える」最初の完成版 |
| IndexedDB | ブラウザの中にある端末内データベース。画像も保存できる。本アプリの**正のデータ**（＝本物の原本）はここ |
| localStorage | ブラウザの小さな保存領域。設定値など小さな文字データだけを入れる |
| Service Worker | アプリのファイルを端末にキャッシュ（一時保存）し、オフラインでも開けるようにする裏方プログラム |
| Apps Script（GAS） | Google Apps Script。Googleが無料で提供するプログラム実行環境。スプレッドシートへの書き込み窓口として使う |
| 合言葉（トークン） | Apps Scriptに送るときに添える簡易パスワード。知らない第三者がシートに書き込むのを防ぐ |
| UUID | 世界で重複しないランダムなID（例：`3f2b…`）。決済時に同じ記録を見つけたり、シートの同じ行を更新したりするのに使う |
| pips | 為替の値幅の単位。USD/JPYなど円絡みは 0.01円＝1pip、EUR/USDなどは 0.0001＝1pip（詳細は `docs/fx-rules.md`） |
| ロット（lot） | 取引数量の単位。1lotが何通貨かは**業者によって異なる**（1万通貨／10万通貨など）ため設定で変更可能にする |
| SL / TP | Stop Loss（損切りライン）／ Take Profit（利確ライン） |
| リスクリワード（RR） | 「利確までの幅 ÷ 損切りまでの幅」。例：SL 20pips・TP 40pips なら 2.0 |
| セッション | 取引が活発な市場の時間帯。東京・ロンドン・ニューヨークなど |
| status | 記録の状態。`open`＝保有中（未決済）、`closed`＝決済済み |
| CSV | カンマ区切りの表形式テキスト。Excelやスプレッドシートで開ける |
| 論理削除 | データを本当に消さず「削除済み」の印を付けて非表示にする方式。誤削除からの復旧やシートへの削除反映がしやすい |
| 物理削除 | データを端末から本当に消すこと。本アプリでは画像の個別削除だけがこれにあたる（F-05） |
| 下書き | 入力途中の内容を端末に一時保存したもの。アプリが閉じられても続きから入力できる（F-01、6.4） |
| 接頭辞 | 名前の先頭に付ける共通の文字。localStorage の実際の保存キーには `fxnote:` を付ける（6.3） |

## 5. 機能要件

**分類**：`MVP`＝最初の完成版に必ず入れる / `拡張`＝MVP後に追加。フェーズは `docs/roadmap.md` に対応。

| ID | 機能 | 分類 | フェーズ | 概要 |
|---|---|---|---|---|

| F-02 | 決済記録 | MVP | 1 | 保有中の記録に決済情報を追加し、pips・損益を自動計算して `status=closed` に |
| F-03 | 一覧・検索・絞り込み | MVP（基本） / 拡張（高度な条件） | 1 / 3 | 記録の一覧表示と条件での絞り込み |

### 5.2 機能ごとの要件

#### F-01 エントリー記録（MVP）
- 必須項目：デモ/本番、通貨ペア、売買方向、エントリー価格、エントリー日時、ロット
- 任意項目：SL、TP、エントリー根拠、時間足、感情、タグ、メモ、画像
- **入力の手間を減らす工夫**（詳細は designer）
  - エントリー日時は「今」を自動入力（変更可）
  - デモ/本番・通貨ペア・ロットは**前回値**を初期表示。**ロットの前回値はデモ/本番で別々に覚える**（口座を切り替えるとその口座で前回使ったロットになる）
  - **売買方向は前回値を引き継がず、毎回選ぶ**（方向の間違いは損益の符号が逆になる重大なミスのため）
  - 通貨ペアは「よく使うペア」を先頭に表示
  - 任意項目は折りたたみ（「詳細（任意）」）にまとめ、必須項目だけで保存可能。**折りたたみは毎回閉じた状態で開く**
  - 入力画面で新しい選択肢を追加できるのは**タグのみ**（追加したタグは設定の選択肢にも加わる）。根拠・感情の選択肢は設定画面で追加する
  - セッションはエントリー日時から自動判定（変更可。判定時刻は `docs/fx-rules.md` 11章）
- SLとTPが両方入力されたらリスクリワードを自動計算して表示
- 方向とSL/TPの関係が不自然な場合（例：買いなのにSLがエントリー価格より上）は**警告を表示するが保存は止めない**
- 保存すると `status=open`、`id`（UUID）・作成日時を自動付与。保存完了が分かる表示を出す
- 保存ボタンには口座区分を表示する（例：「本番で保存」「デモで保存」）。入れ間違いを保存直前に防ぐため
- **入力途中の下書き自動保存**（v1.1追加）：入力中の内容を端末に一時保存し、アプリが閉じられても再度開くと続きから入力できる。保存または破棄で下書きを消す。iPhoneでは業者アプリへ切り替えた際にアプリが終了し入力が消えることがあるため（F-02 決済記録・F-04 編集にも適用）
  - 下書きの保存先は IndexedDB の `drafts` ストア（6.4）
  - アプリを開き直したとき、下書きの最終更新から**30分以内**なら入力画面を自動で開いて続きから入力できる。30分を過ぎていれば一覧に「入力途中のエントリーがあります［続ける］」を出す（v1.2）
- 入力値のチェック（エラー＝保存不可／警告＝保存可）は `docs/fx-rules.md` 8章に従う。価格・ロット・円換算レートの桁数上限はエラー、エントリー価格と決済価格・SL・TPの差が10%以上なら打ち間違いの可能性として警告する。また、価格が通貨ペアごとの**価格帯の目安から外れたら警告**する（W-06。例：USD/JPY に 1.0850 と入れたとき。v1.2）

#### F-02 決済記録（MVP）
- 一覧・詳細から保有中（open）の記録を選び「決済」操作で入力
- 入力：決済価格（必須）、決済日時（必須・「今」を自動入力）、決済理由・決済時の感情・メモ・画像（任意）
- 決済画面を開いたら決済価格の欄にフォーカスし、**数字キーボードを自動で表示**する（v1.2）
- pips と損益（円）を自動計算（計算式は `docs/fx-rules.md`）。損益（円）は業者の確定値で**上書き可能**（確認事項 Q-02）。iPhone の数字キーボードにはマイナスがないため、確定損益は**＋/− の切替＋数字キーボード**で入力する（v1.2）。業者アプリの表示を貼り付けた `+2,480` や全角の `－５，７００` も受け付ける（v1.4。`docs/fx-rules.md` 8.1）
- 保存ボタンには口座区分を表示する（「本番の決済を保存」「デモの決済を保存」）。デモと本番で同じペアを保有しているときの取り違えを防ぐため（v1.2）
- 保存すると `status=closed`
- 決済後も編集で決済情報を修正でき、再計算される
- 誤操作に備え「決済の取り消し（openに戻す）」ができる（確認ダイアログ付き）。取り消すと計算に関わる項目（決済価格・決済日時・pips・損益（円）・損益の算出方法・円換算レート）を消す。決済理由・決済時の感情・メモ・タグ・画像は**残す**（入力した文章や画像を失わないため。再決済時にそのまま使える）

#### F-03 一覧・検索・絞り込み
- **MVP**
  - 新しい順に表示。保有中（open）は上部にまとめて表示（保有中はエントリー日時、決済済みは**決済日時**の新しい順）
  - 各行に：日時、通貨ペア、売買方向、デモ/本番バッジ、status、損益（円・pips。+/− 記号と色で区別）
  - 絞り込み：デモ/本番（初期値「すべて」）、status（保有中/決済済み）、通貨ペア、売買方向、期間、**勝ち/負け/引き分け**（v1.2で引き分けを追加。判定は損益（円）基準で、0円が引き分け）
  - 期間の判定は、保有中＝エントリー日時、決済済み＝決済日時。**週は月曜始まり**（v1.2）
  - キーワード検索：メモ・エントリー根拠・タグを対象
  - 絞り込み結果の**件数・合計損益（円/pips）**を表示。**デモと本番が混在するときは口座ごとに分けて表示**し、混ぜた合計は出さない。pips の合計には「通貨ペア・ロットの違いを考えない単純な合計」と注記する（v1.2）
  - 絞り込み条件は、画面を移動しても保持する。アプリを閉じても**30分以内**に開き直せば復元し、それを過ぎたら初期値に戻す（localStorage の `listFilter`。v1.2）
  - 適用中の絞り込み条件は一覧の上部にチップ（小さな角丸のボタン）で表示し、**チップをタップすると確認なしでその条件だけを解除**できる（2つ以上なら「すべて解除」も出す）。誤って外しても絞り込みの画面ですぐ戻せるため（v1.3。10章 F）
  - 決済済みは決済日ごとに見出しを付け、**記録が1つの口座（本番だけ・デモだけ）のときだけ**見出しにその日の合計損益（円）を出す（v1.3。`docs/design.md` 14.3.5）
  - 詳細は `docs/analytics.md` 4章、画面は `docs/design.md` 14.3
- **拡張**（Phase 3・data-analyst が `docs/analytics.md` で設計）
  - タグ・感情・セッション・時間足での絞り込み、並び替え（損益順など）
  - 絞り込み条件の保存

#### F-04 詳細・編集・削除（MVP）
- 詳細：全項目、自動計算値、添付画像（タップで拡大）を表示。未入力の任意項目も「—」で表示する（入れていなかったことに気づけるように。`docs/design.md` 14.4.4）
- 詳細画面の下部（親指が届く位置）には、保有中なら「決済する」、**決済済みなら「編集」**を置く（右上の「編集」と両方。週末の振り返りでタグ・メモを書き足しやすくするため。v1.3。10章 F）
- 編集：全項目を修正可能。価格やロットを変えたら pips・損益・RR を再計算
  - 口座区分（デモ⇔本番）を変えたときは、1lotの通貨数（`lotUnitSize`）を変更先の口座区分の**現在の設定値でコピーし直して**再計算する。ただし損益（円）を業者の確定値で上書きした記録（`profitSource=manual`）の損益は書き換えない（v1.2。`docs/fx-rules.md` 4.5）
  - **何も変えずに保存したとき**は、保存処理をせず `updatedAt` も変えない。編集では前回値（`lastInput`）も更新しない（`docs/design.md` 14.5.1）
  - **編集を始めたあとに、別の画面で同じ記録が先に変更されていたとき**は、黙って上書きせず知らせる。自分が変えた項目だけを最新の記録に重ねて保存する選択肢を出す（更新日時の食い違いで検出する。更新日時は秒単位なので同じ秒内の変更は検出できない。`docs/architecture.md` 6.12・15.1）。編集中に記録が削除されたときは、入力内容と下書きを消して「この記録は見つかりません」を表示する
  - 通貨ペアを変えたとき、円換算レートは `docs/fx-rules.md` 4.5 のとおり扱う（決済通貨が変わるときはレート欄を空にして入れ直しを促す）
- 削除：**確認ダイアログ必須**。論理削除（`deletedAt` を記録して非表示）とする（確認事項 Q-16）
- 削除直後の通知（トースト）に「取り消す」ボタンを表示し、6秒間は削除を元に戻せる（v1.1追加。秒数は design 9.6）。**6秒を過ぎたら画面からは元に戻せない**。「最近削除した項目」の画面は MVP では作らない（論理削除なのでデータは端末に残っており、必要になれば Phase 4 の改善候補として追加できる。v1.3。10章 F）
- 更新日時を自動記録

#### F-05 チャート画像添付（MVP）
- 端末の写真ライブラリから選択（スマホではカメラ撮影も可）
- 保存前に自動で縮小・圧縮（目安：長辺1280px、JPEG、1枚200KB前後）
- エントリー時・決済時どちらでも添付可。1トレードあたり最大4枚（確認事項 Q-12）
- 詳細画面でサムネイル表示 → タップで拡大、個別に削除可能。個別削除は**確認のうえ物理削除**（画像は大きく同期もしないため、論理削除にしない。v1.2）。入力中でまだ保存していない画像は確認なしで外せる
- 画像は IndexedDB に保存。**スプレッドシートには同期しない**（将来の拡張でGoogleドライブ保存を検討）

#### F-06 分析画面（拡張・Phase 3）
- 指標・グラフの詳細は data-analyst が `docs/analytics.md` で設計。計算式は fx-expert の `docs/fx-rules.md` に従う
- 想定内容：トレード数、勝率、合計損益（円/pips）、平均利益・平均損失、プロフィットファクター（総利益÷総損失）、最大ドローダウン（資産の最大の落ち込み幅）、累積損益グラフ、切り口別（通貨ペア・売買方向・曜日/時間帯・セッション・タグ・根拠・感情）
- **デモと本番は必ず分けて集計**（混ぜて表示しない）
- 件数が少ない切り口（例：5件未満）は「データ不足」と表示
- グラフは Chart.js（CDN・バージョン固定。オフラインでも表示できるよう Service Worker でキャッシュする）

#### F-07 Googleスプレッドシート同期（拡張・Phase 2）
- 構成：PWA →（fetchでPOST）→ Apps Script Webアプリ → スプレッドシート
- 正のデータは端末内（IndexedDB）。シートはバックアップ兼閲覧・集計用
- **IDで「追加または上書き」**：エントリー時に行を追加、決済・編集時は同じ行を更新
- 保存・編集・削除のたびに自動送信。オフライン時や失敗時は**未送信キュー**に溜め、オンライン復帰時・アプリ起動時に自動再送。手動の「今すぐ同期」ボタンも用意
- 同期状態（未送信件数・最終同期日時・エラー内容）を確認できる
- 合言葉をリクエストに含め、Apps Script側で照合
- 画像は同期対象外。同期はアプリ → シートの**一方向**（確認事項 Q-19）
- セットアップ手順は sheets-integrator が `docs/sheets-setup.md` に記載

#### F-08 設定
- **MVP**
  - 1lotあたりの通貨数（例：10,000 / 100,000）。デモ・本番で異なる場合に備え口座区分ごとに設定可能とする（確認事項 Q-01）。**通貨ペアごとの1lot設定は作らない**（高金利通貨は取引しないため。10章 E）
  - よく使う通貨ペアの並び・追加
  - エントリー根拠・タグ・感情の選択肢の編集（確認事項 Q-10, Q-11）
  - 表示テーマ（ライト／ダーク／端末に合わせる）
  - アプリのバージョン表示
- **拡張（Phase 2）**
  - Apps Script WebアプリURL、合言葉の入力（**コードに直書きしない**。localStorageに保存）
  - 接続テストボタン、同期状態の表示
- 設定値の変更は**過去の記録の損益を書き換えない**（記録時点の1lot通貨数を各記録に保存するため）。例外は、記録の編集で口座区分を変えたときだけ（F-04）

#### F-09 CSVエクスポート／インポート
- **エクスポート（MVP）**：全記録（論理削除分を含めるか選択可）をCSVで書き出し。Excelで文字化けしないよう **BOM付きUTF-8**（Excelに「これはUTF-8です」と伝える印付きの文字コード）。画像は含まない
- **インポート（拡張・Phase 2）**：エクスポートしたCSVを読み込んで復元。同じIDがあれば「スキップ／上書き」を選択。取り込み前に件数を確認表示
- 定期的なバックアップを促す表示（例：最終エクスポートから30日経過で案内）は Phase 4 で検討

#### F-10 PWA（MVP）
- `manifest.json` とアイコンを用意し、ホーム画面に追加すると全画面のアプリとして起動
- Service Worker でアプリ本体をキャッシュし、**オフラインでも全機能（同期を除く）が使える**
- アプリ更新時は新しい版に切り替わる。新しい版を見つけたら「新しいバージョンがあります［更新］」と表示し、押したときに切り替える（入力中に勝手に画面が読み込み直されないように。`docs/architecture.md` 12.3）
- GitHub Pages（無料）で公開。リポジトリ名は **`fx-trade-note`**、公開URLは `https://<GitHubユーザー名>.github.io/fx-trade-note/`（v1.2）。リポジトリ名はURLの一部になり、後から変えるとホーム画面版のデータが引き継げないため**変更しない**

## 6. データ項目定義

### 6.1 トレード記録（IndexedDB の `trades` ストア）

> **ストア**＝IndexedDB内の「表」のようなもの。
> **入力タイミング**：エントリー時 / 決済時 / 自動計算（アプリが自動で入れる）。どの項目も後から編集画面で修正できる（自動項目は再計算）。
> **型**：string＝文字、number＝数値、boolean＝はい/いいえ、datetime＝日時（ISO 8601形式の文字列。例 `2026-10-15T21:30:00+09:00`）、enum＝決められた選択肢から1つ、配列＝複数の値の並び。
> Phase 2以降で使う項目（同期状態など）も**MVPの時点から用意**しておき、後からデータ構造を作り変えるリスクを減らす。

| 項目名 | キー名 | 型 | 必須 | 入力タイミング | 説明 |
|---|---|---|---|---|---|
| ID | `id` | string（UUID） | 必須 | 自動 | 記録ごとの一意なID。シート同期でも行の特定に使う |
| デモ/本番 | `accountType` | enum：`demo` / `real` | 必須 | エントリー時 | 口座区分。前回値を初期表示。画面上で一目で区別できる表示にする |
| 通貨ペア | `pair` | string | 必須 | エントリー時 | 例：`USD/JPY`。通貨ペアマスタ（fx-expert定義）から選択 |
| 売買方向 | `side` | enum：`buy` / `sell` | 必須 | エントリー時 | 買い（ロング）／売り（ショート） |
| エントリー価格 | `entryPrice` | number | 必須 | エントリー時 | 約定価格 |
| エントリー日時 | `entryAt` | datetime | 必須 | エントリー時 | 初期値は現在時刻。日本時間で表示 |
| ロット | `lots` | number | 必須 | エントリー時 | 取引数量（lot）。0より大きい値。小数可（例 0.1） |
| 1lotの通貨数 | `lotUnitSize` | number | 必須 | 自動 | 記録時点の設定値（口座区分ごとの値）をコピー。後で設定を変えても過去の損益が変わらないようにするため。編集で口座区分を変えたときだけ、変更先の現在の設定値でコピーし直す（F-04） |
| 損切りライン（SL） | `slPrice` | number | 任意 | エントリー時 | Stop Loss価格（確認事項 Q-06） |
| 利確ライン（TP） | `tpPrice` | number | 任意 | エントリー時 | Take Profit価格 |
| リスクリワード | `riskReward` | number | 任意 | 自動計算 | （TPとエントリー価格の差の絶対値）÷（エントリー価格とSLの差の絶対値）。SL・TP両方あるときのみ。SL/TPが売買方向と矛盾する場合は計算せず空（`null`、画面は「—」）。小数第2位まで（`docs/fx-rules.md` 5章） |
| 決済価格 | `exitPrice` | number | 決済時は必須 | 決済時 | 決済の約定価格 |
| 決済日時 | `exitAt` | datetime | 決済時は必須 | 決済時 | 初期値は現在時刻 |
| pips | `pips` | number | 決済後は必須 | 自動計算 | 買い：決済−エントリー、売り：エントリー−決済 を pip単位に換算。小数第1位まで |
| 損益（円） | `profitJpy` | number | 決済後は必須 | 自動計算（上書き可） | 円換算の損益。プラス＝利益、マイナス＝損失（確認事項 Q-02） |
| 損益の算出方法 | `profitSource` | enum：`auto` / `manual` | 決済後は必須 | 自動 | 自動計算値か、手入力（業者の確定値）で上書きしたかの区別。`manual` の損益は、価格・ロット・口座区分などを編集しても自動で書き換えない |
| 円換算レート | `quoteToJpyRate` | number | 任意 | 決済時 | 円以外が決済通貨のペア（EUR/USD等）の損益を円にするためのレート（例：USD/JPYの値）。入力があれば損益（円）を自動計算、なければ損益（円）を手入力（Q-02） |
| ステータス | `status` | enum：`open` / `closed` | 必須 | 自動 | 保有中／決済済み。決済情報の有無で自動設定 |
| エントリー根拠 | `entryReasons` | 配列（string） | 任意 | エントリー時 | 選択式（設定で編集可）・複数選択（確認事項 Q-11） |
| 時間足 | `timeframe` | enum：`M1` `M5` `M15` `M30` `H1` `H4` `D1` `W1` | 任意 | エントリー時 | 判断に使った主な時間足（M＝分足、H＝時間足、D＝日足、W＝週足） |
| セッション | `session` | enum：`tokyo` / `london` / `newyork` / `other` | 任意 | 自動計算（変更可） | エントリー日時から判定（確認事項 Q-07）。東京＝日本時間9:00〜ロンドンの始まり、ロンドン・NY＝現地8:00から、重なる時間は後から始まる市場を優先、早朝と週末は `other`。夏時間を含む判定時刻は `docs/fx-rules.md` 11章。重なり専用の値（overlap）は設けない（v1.2） |
| エントリー時の感情 | `emotion` | enum（設定で編集可） | 任意 | エントリー時 | 例：冷静／自信／不安／焦り／興奮／取り返したい（確認事項 Q-10） |
| 決済理由 | `exitReason` | enum：`tp` / `sl` / `manual` / `breakeven` / `other` | 任意 | 決済時 | 利確ライン到達／損切りライン到達／裁量決済／建値決済（損益ゼロ付近での決済）／その他 |
| 決済時の感情 | `exitEmotion` | enum（設定で編集可） | 任意 | 決済時 | 選択肢は `emotion` と共通 |
| タグ | `tags` | 配列（string） | 任意 | エントリー時・決済時 | 自由なラベル。例：`ルール違反` `指標前` `様子見すべきだった`（この3つがタグの選択肢の初期値：6.3） |
| メモ | `memo` | string | 任意 | エントリー時・決済時 | 自由記述。最大2,000文字程度 |
| 画像ID一覧 | `imageIds` | 配列（string） | 任意 | エントリー時・決済時 | 添付画像（6.2の `images` ストア）のIDの並び |
| 同期状態 | `syncStatus` | enum：`pending` / `synced` / `error` | 必須 | 自動 | シートへの送信状態。保存・編集のたびに `pending` へ。MVPでは常に `pending` |
| 最終同期日時 | `syncedAt` | datetime | 任意 | 自動 | 最後にシート送信が成功した日時 |
| 削除日時 | `deletedAt` | datetime | 任意 | 自動 | 論理削除した日時。値があれば一覧に表示しない |
| 作成日時 | `createdAt` | datetime | 必須 | 自動 | 記録を作った日時 |
| 更新日時 | `updatedAt` | datetime | 必須 | 自動 | 最後に変更した日時 |

**自動計算の補足**
- 保有時間（決済日時−エントリー日時）や曜日・時間帯は保存せず、表示・分析時にその場で計算する
- 計算結果の丸め（桁数）や浮動小数点誤差（コンピュータの小数計算で生じるごく小さなズレ）の扱いは `docs/fx-rules.md` に従う

### 6.2 画像（IndexedDB の `images` ストア）

| 項目名 | キー名 | 型 | 必須 | 入力タイミング | 説明 |
|---|---|---|---|---|---|
| 画像ID | `id` | string（UUID） | 必須 | 自動 | 画像ごとの一意なID |
| トレードID | `tradeId` | string（UUID） | 必須 | 自動 | どのトレードの画像か |
| 添付タイミング | `kind` | enum：`entry` / `exit` | 必須 | 自動 | エントリー時・決済時のどちらで添付したか |

### 6.3 設定（localStorage）

> **実際の保存キーには接頭辞 `fxnote:` を付けます**（例：`lotUnitSize.demo` → `fxnote:lotUnitSize.demo`）。GitHub Pages では同じアカウントの他のアプリと保存領域を共有するため、名前の衝突を防ぐ目的です。下表のキー名（接頭辞を除いた部分）は変えません（`docs/architecture.md` 7.1。v1.2）。
> localStorage には設定値と、一覧の絞り込み条件の一時保存（`listFilter`）だけを入れます。トレード記録・画像・下書きは IndexedDB に保存します。

| 項目名 | キー名 | 型 | 初期値（案） | フェーズ | 説明 |
|---|---|---|---|---|---|
| 1lotの通貨数（デモ） | `lotUnitSize.demo` | number | 10,000 | 1 | 確認事項 Q-01（決定） |
| 1lotの通貨数（本番） | `lotUnitSize.real` | number | 10,000 | 1 | 確認事項 Q-01 |
| よく使う通貨ペア | `favoritePairs` | 配列 | USD/JPY, EUR/USD, GBP/JPY, EUR/JPY, AUD/JPY, GBP/USD | 1 | 確認事項 Q-05。高金利通貨（ZAR/JPY 等）はプリセットに含めない（「その他」から選べる） |
| 前回入力値 | `lastInput` | object | なし | 1 | 前回の口座区分・通貨ペアと、**口座区分ごとの前回ロット**（例：`{ accountType, pair, lots: { demo, real } }`）。**売買方向は含めない**（毎回選ぶ）。**新規エントリーの保存に成功したときだけ**更新し、決済・編集では更新しない（v1.2、v1.3 で明確化） |
| 一覧の絞り込み条件 | `listFilter` | object | なし | 1 | 一覧の絞り込み条件と保存日時（`{ version, savedAt, filter }`）。アプリを開き直したとき、保存から30分以内なら復元する（F-03、`docs/analytics.md` 4.8。v1.2追加） |
| 根拠・感情・タグの選択肢 | `choices` | object | 3種類の初期値は次のとおり（2026-10-16 確定）。**根拠 `entryReasons`**：トレンドフォロー／押し目買い・戻り売り／ブレイクアウト／レンジ逆張り／経済指標・ニュース／その他（Q-11）。**感情 `emotions`**：冷静／自信／不安／焦り／興奮／取り返したい／退屈（Q-10）。**タグ `tags`**：ルール違反／指標前／様子見すべきだった（6.1 の例） | 1 | ユーザーが編集可能。初期値は `js/master.js` の `DEFAULT_CHOICES` に置き、`js/settings-store.js` はそこから読む（T-15 の時点では `settings-store.js` に仮置きしていたが、T-16 で `master.js` へ移した：architecture 7.1） |
| テーマ | `theme` | enum：`auto` / `light` / `dark` | `auto` | 1 | ダークモード切替 |
| 最終エクスポート日時 | `lastExportAt` | datetime | なし | 1 | バックアップ案内に使用 |
| Apps Script URL | `gasUrl` | string | なし | 2 | コードに直書きしない |
| 合言葉 | `syncToken` | string | なし | 2 | コードに直書きしない。画面上は伏せ字表示 |

### 6.4 下書き（IndexedDB の `drafts` ストア）（v1.2追加）

> 入力途中の内容を一時保存する場所です（F-01 の下書き自動保存）。画像（`images`）と同じ IndexedDB に置くことで、「記録の保存＋下書きの削除」を1回の処理で確実に行えます。シートには同期せず、CSV にも出力しません。詳細な動き（保存のタイミング・復元・削除）は `docs/architecture.md` 6.5・9章、画面での見え方は `docs/design.md` 14.1.10。

| 項目名 | キー名 | 型 | 必須 | 説明 |
|---|---|---|---|---|
| 下書きキー | `key` | string | 必須 | `new`（新規エントリー）／`close:{トレードID}`（決済）／`edit:{トレードID}`（編集）。同じ画面の下書きは常に1つ |
| 種類 | `kind` | enum：`new` / `close` / `edit` | 必須 | どの入力画面の下書きか |
| トレードID | `tradeId` | string（UUID） | 必須 | 対象のトレード。新規は入力画面を開いた時点で採番したID（画像を先に保存するため） |
| 入力内容 | `fields` | object | 必須 | 入力欄の値を**入力した文字のまま**保存（例 `entryPrice: "150.10"`）。項目名は 6.1 のキー名に合わせる |
| 画面の状態 | `uiState` | object | 任意 | 「詳細（任意）」の開閉、保存・キャンセル後の戻り先など |
| 追加した画像 | `addedImageIds` | 配列（string） | 必須 | この入力中に追加した画像のID（破棄したら画像も削除） |
| 外した画像 | `removedImageIds` | 配列（string） | 必須 | 編集中に外した画像のID（保存したときに削除） |
| 元の更新日時 | `baseUpdatedAt` | datetime | 任意 | 決済・編集の下書きで、元の記録の `updatedAt`。元の記録が別の操作で変わっていないかの確認に使う |
| 作成日時・更新日時 | `createdAt` / `updatedAt` | datetime | 必須 | 下書きを作った日時・最後に自動保存した日時。`updatedAt` から30分以内なら起動時に入力画面を自動で開く |

## 8. 非機能要件

> 非機能要件＝「何ができるか」ではなく「どれくらい快適・安全か」の品質面の要求。

| 分類 | 要件 | 確認方法 |
|---|---|---|
| 操作性（最重要） | スマホ片手で、アプリ起動からエントリー記録（必須項目のみ）の保存完了まで**30秒以内**。決済記録は**20秒以内**を目標 | ux-tester がモバイルサイズで時間とタップ数を計測、オーナー実機確認 |
| 操作性 | タップ領域は最低44×44px、数値入力欄は数字キーボードを表示、主要ボタンは画面下部 | designer の設計・ux-tester |
| 操作性 | デモ/本番、買い/売り、利益/損失が一目で区別できる（色だけでなく文字・記号でも区別）。ダークモード対応 | ux-tester |
