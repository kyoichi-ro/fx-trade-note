## 5. Phase 2/3 の順番とタスクの見直し（決定：2026-10-19・推奨どおり）

### 5.1 推奨：Phase 2（スプレッドシート同期）を先にする

| 理由 | 内容 |
|---|---|
| 1. 今のバックアップは手動の CSV だけ | しかも**アプリ内に CSV を読み込む機能がない**（T-44 は Phase 2）。書き出せても戻せないので、バックアップとして片方しかない。端末が壊れる・誤って消すと戻せない |
| 2. 分析は記録が貯まってから価値が出る | Phase 3 は「5件未満は『データ不足』」とする設計で、記録が少ないうちは空に近い画面になる。オーナーは使い始めたばかり（2026-10-19）。Phase 2 を作る間に記録が貯まり、分析の設計も実際の記録を見ながら決められる |
| 3. Phase 2 は画面の変更が少ない | 中心は Apps Script とシートの設計で、アプリの画面は「設定の同期グループ」と「同期状態」だけ。オーナーの普段使いを邪魔しにくい |
| 4. シートで暫定の集計ができる | 同期が動けば、スプレッドシートのフィルタやピボット（集計表）で、勝ち負けの切り口別の確認が Phase 3 の前にできる。「先に分析を見たい」要望への代替になる |

**Phase 3 を先にする場合の見方**：「勝ちパターン・負けパターンに気づく」がこのアプリの目的なので、分析を早く見たい気持ちが記録の継続に効く可能性はある。ただし、上の2のとおり、今の記録数では見えるものが少ない。順番を入れ替えても Phase 2・3 は互いに依存しないので、後から入れ替えられる。
