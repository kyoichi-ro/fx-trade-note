## 指摘一覧

### CI-R01（中）根拠・タグ・感情（エントリー時・決済時）の文字に長さ・個数の上限がなく、巨大な値をそのまま DB に入れる
- 該当：js/csv-import.js:261-265（list：根拠・タグ）、js/csv-import.js:267-270（optionalText：感情）、js/csv-import.js:332-335。比較：メモだけは js/csv-import.js:337 で2,000文字の上限あり。js/csv-import.js:612-627（planChoiceAdditions は件数の上限なし）
- 何が起きるか（Node で実行して確認）：
  - 感情のセルに 100,000 文字を入れた CSV が「読めた行」として通る（20MB 未満なら1セル 19MB でも通る）。画面からは選択肢（20文字以内）からしか入らない値なので、CSV だけが作れる記録になる。
  - Phase 2 の Apps Script は文字の列が 50,000 文字を超えると `TOO_LONG`、要求全体が 2,000,000 文字を超えると `TOO_LARGE` で受け付けない（gas/Code.gs:63・65）。その記録は何度送っても届かず、まとめて送る作り（T-41）だと同じ回の他の記録まで止まるおそれがある。
  - タグの種類が数千ある CSV を取り込むと、削除済みでない記録のタグがすべて選択肢の末尾に足される（上限なし）。エントリー画面のタグの欄が数千個のチップになる。
  - 画面が落ちることはなく XSS にもならない（h() でテキストとして入る）が、「壊れた CSV で DB を汚さない」という T-44 の約束からは外れる。取り込み後は記録の編集でしか直せない。
- 修正案：根拠・タグ・感情の各要素に選択肢と同じ上限（CHOICE_NAME_MAX_LENGTH＝20文字。checkChoiceName と同じ数え方）を当て、超えたら「〜が長すぎます」で読めない行にする。根拠・タグの要素数にも上限（例：20個）を付ける。少なくとも Apps Script の 50,000 文字は超えないようにする。planChoiceAdditions で1回に足す数にも上限（例：種類ごとに50件）を検討する。

### CI-R02（低）ID の大文字を受け付けるため、同じ記録が2件になる・シートに送れない記録ができる
- 該当：js/csv-import.js:55（UUID_PATTERN に `i` フラグ）、js/csv-import.js:297、js/csv-import.js:452-457（重複判定は大文字小文字を区別）、gas/Code.gs:85（Apps Script は小文字だけ）
- 何が起きるか（Node で実行して確認）：ID を大文字に書き換えた行も「読めた行」になる。端末の記録（util.js の newId は小文字）と別の ID とみなされるので「新しい記録」として追加され、同じトレードが2件になる（一覧・集計で二重に数えられる）。同じ CSV の中に小文字と大文字の同じ ID があっても「同じIDの行」と判定されない。さらに Phase 2 では Apps Script が `BAD_ID` で拒否するので、その記録は永久に未送信のまま。手で直された CSV でしか起きない。
- 修正案：`i` フラグを外して小文字だけを受け付ける（「IDの形が違います」）。または読み込み時に toLowerCase() してから重複判定・端末との照合に使う（Apps Script とそろえるなら前者が簡単）。

### CI-R03（低）更新日時・作成日時の前後関係と「未来の日時」を確かめていない
- 該当：js/csv-import.js:347-349（createdAt・updatedAt・deletedAt は形と年だけ）、js/trades.js:218-225（updatedAt は CSV の値のまま）、js/trades.js:311（saveTrade は updatedAt＝今）
- 何が起きるか（Node で実行して確認）：`updatedAt` が 2099-12-31 の行、`createdAt` が `updatedAt` より後の行も読めた行になる。未来の `updatedAt` で取り込んだ記録は、そのあと端末で編集すると `updatedAt` が「今」（取り込んだ値より前）に戻るため、
  - Phase 2：シートは「届いた updatedAt が古ければ書かない」（sheets-setup 6.1）ので、その記録の以後の編集は 2099 年までシートに届かない（エラーにもならず「古いので書かなかった」になる）。
  - 次に CSV を読み込んだとき、「端末の方があとで更新されています」の注意が出ない（文字の比較が逆転する）。
  - 手で直した CSV のほか、時計が進んでいた別の端末で書き出した CSV でも起きる。
- 修正案：`updatedAt` が今より（余裕を見て1日以上）後なら「更新日時が未来です」で読めない行にする。`createdAt > updatedAt` も読めない行にする。あわせて saveTrade 等で `updatedAt = max(今, 保存されている updatedAt)`（R-05 の対策と一緒に）にしておくと、未来の値が入っても順序が崩れない。

### CI-R04（低）円換算レートに上限がなく、極端な値の記録は書き出しても読み戻せない。保有中の記録に円換算レートがあっても通る
- 該当：js/validate.js:146-152（parseQuoteToJpyRate に上限なし）、js/csv.js:120（数値は String(v)）、js/csv-import.js:58（CSV_NUMBER は指数表記を受け付けない）、js/csv-import.js:354-361・383-390（保有中のときに円換算レートを見ていない）
- 何が起きるか（Node で実行して確認）：決済画面で円換算レートに 1e21 以上（22桁の数字）を入れると保存でき、書き出しで `1e+21` になる。その CSV を読むと「円換算レートが数値ではありません」になり、**自分で書き出した記録が戻らない**（往復が崩れる唯一の例として確認。現実のレートではまず起きない）。また、保有中の行に円換算レートがあっても読めた行になり、アプリが作らない形（保有中なのにレートあり。決済の取り消しは null に戻す：fx-rules 4.5）の記録ができる。
- 修正案：parseQuoteToJpyRate に価格と同じ上限（1,000,000 未満など。fx-expert と決める）を足す（R-01 と同じ扱い）。readClose の保有中の分岐に「保有中なのに円換算レートがあります」を足す。

### CI-R05（低）上書きでは、端末と全く同じ記録（updatedAt も同じ）も書き直して未送信（pending）に戻す
- 該当：js/trades.js:485-495（overwrite のときは比べずに全件を書く）、js/trades.js:218-225（syncStatus は必ず pending）
- 何が起きるか：直前に書き出した CSV を「上書き」で読み込むと、何も変わっていない記録も「上書きした記録 n件」と数えられ、`syncStatus` が `synced` から `pending` に戻る。Phase 2 で同期を設定していると、変わっていない全件（数千件）をシートに送り直すことになる。データは失われないが、結果の件数が実態と合わず、送信量が増える。
- 修正案：上書きでも、端末の記録と `updatedAt` が同じで、内容（画像・同期の項目を除く32項目）も同じなら書かずに「変わらなかった」として数える（結果の行は「上書きした記録」に含めないか、design に「変更なし」の扱いを相談）。少なくとも `syncStatus` は内容が同じなら端末の値を残す。

### CI-R06（低）上書きした記録の画像が端末にない場合も「画像は戻っていません」が出ない
- 該当：js/screens/settings-import.js:166（新しい記録だけを数える）
- 何が起きるか：CSV の imageCount が1以上で、端末の同じ記録に画像が無い（または少ない）ときに上書きすると、画像は戻っていないのに結果の注記が出ない（UI で確認：画像1枚の記録を、画像なしの端末の記録に上書き → 注記なし）。データには影響しない。
- 修正案：上書きした記録は「CSV の imageCount > 端末の imageIds.length」のときも数える（importTrades の結果に stored を返すか、summarizeImport で端末の枚数を見ておく）。

### CI-R07（低・iPhone 実機で確認が必要）見えないファイル選択が `hidden`（display:none）で、画像の添付で実機確認済みの作りと違う
- 該当：js/screens/settings-import.js:245（`hidden: true`）。比較：js/ui/image-field.js:103（`class: 'visually-hidden'`。T-35 で iPhone 実機確認済み）
- 何が起きるか：Chromium では display:none の `<input type="file">` を click() してもファイル選択が開き、change も届く（UI で確認）。iOS Safari でも近年の版は開けるとされるが、このアプリで実機確認済みなのは画像の「見えないが表示はされている」作りの方。もし開かない版があると「CSVを読み込む」を押しても何も起きない（データは壊れない）。
- 修正案：画像の欄と同じ `visually-hidden` のクラスにそろえる（確認済みの作りに寄せる）。どちらにしても T-44 の実機確認（design 14.6.9「選べるのは CSV だけ」）の際に、開く・選べる・同じファイルを2回選べることを確かめる。
