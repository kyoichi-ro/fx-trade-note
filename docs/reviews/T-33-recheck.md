### RC-01（中）RL-06 の基準が「公開中の版」と一致しない場面があり、上げ忘れを見逃す／上げているのに不合格になる
- 該当：tests/release.test.js:224-234（findReleaseBase：① `@{upstream}` → ② APP_VERSION の行を最後に変えたコミット）、docs/architecture.md:1272（19.1 の手順③）・:953
- 何が起きるか（上の S-02 の表で実測）：
  - **誤合格①**：作業ブランチを `push -u` すると追跡先が `origin/作業ブランチ` になり、公開元の main とではなく「最後に push した作業ブランチ」と比べる。css を直して版を上げずに push した後に実行すると「変更なし」で合格し、そのまま main に取り込むと直した版がスマホに届かない（S-02 の元の被害そのもの）
  - **誤合格②**：main でも、push した後に実行すると基準＝今の状態になり、常に合格する。19.1 には「push の前に」の一言がない
  - **誤不合格**：追跡先のないブランチ（Claude Code の作業ブランチの作り方）や detached HEAD では②になり、「版を上げたコミットの後に直したファイル」をすべて上げ忘れと判定する。今の HEAD（0.2.0・未公開のひとまとまり）でも「css/base.css ほか26件が変わっています」で不合格になり、`node tests/run-node.mjs` が終了コード1で終わる。不要な版上げ（0.2.1）を招く
  - 補足：①で手元の origin/main が古い（fetch していない）と、比べる相手も古くなる
- 修正案：
  1. 基準を公開元に固定する：`git rev-parse --verify --quiet origin/main` があればそれ、なければ `@{upstream}`。② の「APP_VERSION を最後に変えたコミット」は誤不合格の元なのでやめ、公開元が見つからなければ「スキップ（公開元の origin/main が見つからないため）」にする
  2. actual の文に「push の前に実行してください。基準を最新にするには `git fetch` を」の一言を添える（今も基準の名前は出ている）
  3. architecture 19.1 の手順③を「**push（公開）する前に** `node tests/run-node.mjs` を実行」に直し、「リリース確認」の件数を10件にする（RC-04 と合わせて）
