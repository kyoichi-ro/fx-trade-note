## 指摘一覧

### SY-R01（低）URL の欄の高さが、画面の幅が変わっても合わせ直されず、URL の末尾が隠れて見えなくなる
- 該当：js/ui/fields.js:128-136（resize）・js/ui/fields.js:152・156（高さを合わせるのは入力したときと、作った直後の1回だけ）、css/screens.css:837-845（4行以内のときは overflow: hidden のまま）
- 何が起きるか（ヘッドレス Chromium で確認）：110文字の URL を保存した状態で、横向き（幅 844px）で設定を開くと3行の高さになる。そのまま縦向き（幅 390px）にすると、中身は4行になるのに欄は3行の高さのまま・`is-scroll` も付かないので、**最後の行（`/exec` を含む）が隠れ、スクロールもできない**（clientHeight 69px／scrollHeight 92px）。開き直すか1文字入力すると直る。iPhone の文字サイズの変更（Dynamic Type）でも同じことが起きうる。データには影響しないが、design 14.6.8 が縦積みにした理由（「貼り付けた URL が正しいか目で確かめられる」）が崩れる。
- 修正案：`window` の `resize`（または欄に ResizeObserver）でも resize を呼ぶ（画面を離れるときに外す）。簡単に済ませるなら、4行以内でも `scrollHeight > clientHeight` のときは `is-scroll` を付ける。メモ欄（textareaRow：js/ui/fields.js:178-185）も同じ作りで、既存の画面にも同じ現象がある（T-40 で入ったものではない）ので、直すなら一緒に。

### SY-R02（低）保存済みの URL・合言葉を、読み込むとき・送る直前に確かめていない（T-41 の自動送信の前に塞いでおきたい）
- 該当：js/settings-store.js:126-127（gasUrl・syncToken の確認は「空でない文字」だけ）、js/screens/settings-sync.js:115・199・206（configured() は保存値があるかだけを見て、そのまま ping に渡す）、js/sync.js:148-175（postToAppsScript は url を確かめずに fetch）
- 何が起きるか：localStorage の `fxnote:gasUrl`・`fxnote:syncToken` に U-1〜U-4・K-1〜K-4 を通らない値が入っていても（手で書き換えた・今後のコードの誤り・同じ github.io のほかのページ〔architecture 14.4〕）、設定画面はその値をエラーなしで表示し、接続テストを押せ、**合言葉をその URL に送る**。今は CSP の connect-src が送り先を `https://script.google.com`・`https://script.googleusercontent.com` に限るので、外のサイトや http には届かない（被害は小さい）。ただし T-41 では、画面を開かずに保存のたびに自動で送るので、入口で1回確かめただけの値を検証なしで使う形が広がる。
- 修正案：送る窓口を1つ（postToAppsScript）にそろえる方針なので、そこ（または pingAppsScript と T-41 の送信の入口）で `checkGasUrl(url)`・`checkSyncToken(token)` を通らなければ送らず「未設定」と同じ扱いにする。あわせて、設定画面を開いたときに保存値を同じチェックにかけ、通らなければ行を赤にして接続テストを押せなくする（エラー文は今の U-・K- の文でよい）。

### SY-R03（低・designer に戻す）T-6 の文が「シートの準備」に案内するが、T-6 にまとめた原因の多くはそこでは直らない
- 該当：js/sync.js:205（`scriptError` の文。design 14.6.8 の T-6 の文どおり）、docs/sheets-setup.md 12.13 ①（T-6 のときは「設定を確認する」を見る、と書いてある）、docs/sheets-setup.md 13.2 の designer ③（分けるかの判断が design に反映されていない）
- 何が起きるか（偽の Apps Script で確認）：`TOKEN_NOT_SET`（Apps Script 側の合言葉が未設定）、`INTERNAL`＋`SHEETS_API_NOT_ADDED`（サービスの追加忘れ。1.1.0 から）、`UNSUPPORTED_VERSION`（コードが古い）、`HEADER_MISMATCH`、`ok:true` だが `action` が ping でない応答が、すべて「Apps Scriptでエラーが起きました。手順書の『シートの準備』を確認してください。」になる。手順書の「シートの準備」（手順3）をやり直しても直るのは `HEADER_MISMATCH`・`NO_SPREADSHEET` の一部だけで、合言葉（手順5）・サービスの追加（2-3）・新バージョンのデプロイ（12.12）には行き着かない。手順書 12.13 は「設定を確認する」を見るよう書いており、アプリの文と食い違う。T-40 の完了条件（オーナーの iPhone で接続テスト）でこの文が出ると迷う。
- 実装は design の文のとおりなので、実装の誤りではない。開発者ツールには code・reason が出ている（`scriptError（INTERNAL / SHEETS_API_NOT_ADDED）`）が、iPhone では見られない。
- 修正案（designer の判断）：文を「Apps Scriptの設定に問題があります。スプレッドシートのメニュー『FXトレード記録』→『設定を確認する』で確かめてください。」のように 12.13 と同じ入口にする。または 13.2 ③ の提案どおり `TOKEN_NOT_SET`・`SHEETS_API_NOT_ADDED`・`UNSUPPORTED_VERSION`・`HEADER_MISMATCH` を別の文に分ける（コードは classifyPingResponse がすでに code・reason を返しているので、文の表を足すだけで済む）。

### SY-R04（低）見えない文字（ゼロ幅スペース U+200B など）が混ざった URL で、見た目と合わないエラー文になる・そのまま保存される
- 該当：js/sync.js:72-74（normalizeSyncText は trim だけ。trim と `\s` は U+200B〜U+200D・U+2060 を取り除かない）、js/sync.js:97・107
- 何が起きるか（Node で実行して確認）：
  - 末尾に U+200B が付いた URL → U-4「末尾が /exec のURLを入力してください。」（欄には /exec で終わる URL が見えているので、利用者には直し方が分からない）
  - 先頭に付いた URL → U-1、途中に入った URL → **正しい URL として保存**され、接続テストは T-3（届かない）になる
  - 合言葉に入ると K-3「半角の英字・数字・記号で入力してください。」（見た目はすべて半角）
  - Web ページ・チャット・一部のメモアプリからのコピーで混ざることがある。データには影響しない。
- 修正案：normalizeSyncText で前後の空白に加えて U+200B〜U+200D・U+2060・U+FEFF を（途中も含めて）取り除く。合言葉は Apps Script 側が ASCII しか認めない（TOKEN_FORMAT）ので、取り除いても Apps Script の合言葉と食い違うことはない。取り除かない方針なら、U-・K- とは別に「見えない文字が含まれています。コピーし直してください。」を出す（designer に相談）。

### SY-R05（低・ドキュメント）仕様書が実装（合言葉 12文字・K-3・K-4）に追いついていない
- 該当：docs/design.md:3196-3197（K-2 が「仮に8文字」「8文字以上」のまま。K-3・K-4 の行が無い）、docs/sheets-setup.md 12.13 の「アプリの入力欄のエラー」の表（「最終の文は T-40 で決まる」のまま。K-3・K-4 の文が無い）、docs/architecture.md 4.2 のファイル一覧（js/screens/settings-sync.js・ui/fields.js の secretRow／stackedLineRow が無い）・13.2 のテスト件数、docs/roadmap.md の T-40 の状態
- 何が起きるか：実装は sheets-setup 11.6・13.2 に従って 12〜128文字・半角のみ（K-1→K-3→K-2→K-4）で正しいが、design の表を見て作業する人（ux-tester・T-43 の担当）が「8文字で通るはず」と食い違いを報告する、あるいは誤って直すおそれがある。オーナーが手順書 12.13 で K-3・K-4 の文を探しても載っていない。
